# 眼在手上标定与棋盘位姿

`sieans-handeye` 1.0.0，MIT，开发预览版新增，**不包含在已发布的 0.2.0 ZIP 中**。使用现有 NumPy、OpenCV、Pillow，不新增依赖。包含三个算子、四个演示，参数与十二列采样姿态采用表单/表格和变量绑定。

上游依据：[OpenCV 官方手眼变换定义](https://docs.opencv.org/5.0/main_modules/calib.html#calibratehandeye)、[OpenCV GitHub Park 实现参考](https://github.com/opencv/opencv/blob/4.x/modules/calib3d/src/calibration_handeye.cpp)。当前固定的 OpenCV 5.0.0 Python 包不暴露 `calibrateHandEye`；本插件使用 NumPy 独立实现 Park 思路的旋转对齐与平移最小二乘，OpenCV 用于棋盘角点、Rodrigues 和 IPPE/PnP。没有降级或替换原有 OpenCV。

## 支持的安装方式与方向

本版只支持**眼在手上**：相机刚性安装在工具上，标定板固定在基座环境中。定义 B 为基座、G 为工具、C 为相机光学坐标、T 为标定板，则每组同步观测满足：`B_T_G × G_T_C × C_T_T = 固定标定板在基座中的位姿`。

输入机器人位姿必须是“工具→基座”，相机观测必须是“标定板→相机”。输出为“相机→工具”，不是“相机→基座”。如需基座坐标，还必须结合对应时刻的工具→基座位姿；此插件不直接生成机器人动作。固定外部相机的眼在手外方式尚不支持，不能仅交换坐标系名称使用。

## 操作流程

1. 先完成相机内参标定，并固定分辨率、焦距、对焦及裁剪设置。添加“棋盘格位姿 · 标定板到相机”，绑定完整针孔相机内参，填写实际格边长及 mm/m 单位。默认 9×6 是内角点，对应 10×7 个方格。
2. 在机器人停止、图像稳定时采集一帧。算子输出 `pose`，含 x/y/z 平移及 rx/ry/rz **Rodrigues 轴角向量（弧度）**。这不是 XYZ 欧拉角。图像显示角点和坐标轴，结果给出原点像素位置与重投影误差；标注仅作为显示图，不进入下游原图。
3. 普通棋盘没有唯一编码原点。标记并核对每张图的同一物理角点和 X/Y 方向；必要时使用“反转角点顺序”。仅靠检测返回顺序不能保证跨姿态编号一致。位姿双解歧义较大时会拒绝输出，建议增加倾斜及视野覆盖。若把最小误差差距设为 0，即显式放宽该歧义检查。
4. 同时记录该停止姿态下的机器人“工具→基座”位姿。至少六组不同姿态，建议十组以上并绕不同轴变化。软件不自动移动机器人，也没有联机同步采样向导；目前由操作者记录同步数据。
5. 添加“眼在手上 · 多姿态手眼标定”。在十二列采样表中，每行填机器人 X/Y/Z/Rx/Ry/Rz 和对应相机 X/Y/Z/Rx/Ry/Rz。机器人平移单位、相机平移单位分别选择；相机旋转始终为弧度轴角。机器人旋转可选弧度轴角，或固定轴 `Rz(z) × Ry(y) × Rx(x)` 的角度值。不能直接粘贴其他厂家未确认约定的角度。
6. 相机、工具、基座、标定板坐标系名称均需明确且不同。将输出 `calibration` 绑定至流程或全局变量，将 `reference` 也保留在另一个变量。模型兼容 [3D 坐标转换](../sieans-rigid/README.md)，包含输入/输出单位及方向。
7. 另取至少三组**未参与拟合**的同步姿态，添加“手眼标定 · 独立姿态验证”，绑定上述模型和参考记录。验证对照原标定板基座位姿，不重新拟合；超限返回 `passed=false`，供条件分支使用。标定板被移动或相机/工具安装变化后，旧参考不能继续直接使用。

姿态表支持 6–100 行拟合、3–100 行验证，界面按表格分页编辑；可整表绑定变量。可用 [流程记录算子](../sieans-records/README.md) 按字段绑定机器人/棋盘结果、逐轮追加并映射为十二列，再通过条件分支进入拟合。实际采集同步仍由流程及操作者保证，当前没有联机采样向导。后台结构化存储，不要求在工作台编辑配置文本。

## 求解与质量边界

深度相机的点云坐标可能属于深度光学坐标，而棋盘位姿来自彩色光学坐标。必须先根据 SDK 的真实外参完成两者转换，再使用同一相机坐标定义的手眼模型；不能仅修改 frame 字符串来套用。当前插件不自动完成 RGB-D 光学坐标之间的转换。

- 采用相对运动 AX=XB，旋转对数向量对齐后求平移最小二乘。只支持 Park 求解；Tsai/Horaud 等方法未在本版提供。
- 拒绝少量/重复姿态、缺乏至少 5° 的旋转变化、近似平行轴、旋转/平移病态方程、错误矩阵、无效单位及标定板原点不在相机正 Z 前方等输入。相对旋转超过 175° 的运动对不参与求解，以避免近 π 旋转对数符号不稳定。
- 拟合后检查所有采样还原出的固定标定板位姿：平移 RMS、最大单次平移误差和最大角度误差都须满足门限，否则不输出新模型。**平移门限始终按毫米填写，角度门限按度**；结果平移误差及模型平移则按所选机器人单位输出。毫米与米的声明和换算是明确操作，不估计未知比例。
- 棋盘位姿采用原内参及五系数畸变模型，拒绝尺寸不符、不可见完整棋盘、负深度、重投影误差超限及有明显旋转差异的近似等误差双解。不支持鱼眼或其他畸变模型。标注 JPEG 限 1 MB，超过时需降低采集分辨率。
- 低重投影/固定板一致性残差只说明模型与采样的一致程度，不等于实际抓取精度。还需在工作空间中用独立点、标定板和实际工件验证。机器人位姿误差、图像/位姿不同步、板不平、角点原点变化、工具或相机松动都可能影响结果。

## 演示与证据

四个演示：棋盘位姿、八姿态拟合加三姿态独立验证、独立采样偏差 10 mm 检出、手眼模型传给刚体点位转换。八姿态数据的已知相机→工具平移为 (30,-20,80) mm。棋盘图像及姿态均为程序生成，不是实机采样。

`npm run test:handeye` 包括九项 Python 数值/图像测试：已知旋转/平移、单位混用与毫米门限、显式欧拉角约定、恒等变换、平行轴/重复/错误类型、PnP/双解拒绝，以及十一张栅格图像→角点/PnP→手眼求解→独立验证。合成图像测试使用已知物理原点选择反转标志，不把该信息当作生产图像自动识别能力。

另有三项真实 Python 插件流程/三级变量/回滚/Node-RED 桥接测试，以及 HTTP 插件发现、十二列元数据、工程/模型保存、独立误差判定与服务重启。相关 62 项回归及语法检查通过。实际机器人/工业相机、采样同步、工作空间精度、Linux 和界面可视验收仍未完成。
