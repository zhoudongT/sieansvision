# 流程记录处理与采样累积

`sieans-records` 1.0.0，MIT，Python 标准库实现，无新增依赖。属于 0.3.0-dev 开发预览，未包含在已发布的 0.2.0 ZIP 中。工具箱提供七个可拖入流程的扩展算子：创建记录、追加/去重、筛选、排序、按行读取、字段映射、数值统计。

参考 [Node-RED 核心节点的数据修改方式](https://nodered.org/docs/user-guide/nodes) 及 [官方 GitHub Split/Join 源码](https://github.com/node-red/node-red/blob/main/packages/node_modules/@node-red/nodes/core/sequence/17-split.js)。本实现处理单轮输入的有界记录数组；它不拆成异步消息流，也不提供跨消息自动汇合或无损队列。

## 典型流程

1. 定义流程变量 `inspectionRecords`，初始值为空数组。
2. 添加“按字段创建记录”，在结构体字段表中定义名称、类型和输入绑定。例如采样序号绑定流程计数器、检测数量绑定上游几何结果、位姿字段绑定相机/机器人结果。输出 `record` 可绑定 `flow.currentRecord`。
3. 添加“记录表追加与去重”：输入记录表绑定 `flow.inspectionRecords`，待追加记录绑定 `flow.currentRecord`，输出 `records` 再绑定回 `flow.inspectionRecords`。设置容量、满表策略及可选的去重键。
4. 下游用“记录筛选与排除”保留合格项或剔除异常项；用“记录字段稳定排序”和“按行读取记录”取得最大、最小或特定记录；用“记录数值字段统计”获得均值等结果。
5. 运行画面的表格组件绑定 `flow.inspectionRecords`，数值组件绑定输出计数或统计变量。整个过程通过表单/字段表及绑定完成，不需要编写自定义脚本。

插件本身不保存记录。工作台通过三级变量输出绑定，在完整流程成功时统一提交；失败/取消不提交本轮新表。全局/流程/模块变量均可使用。Node-RED 通用扩展算子也能调用这些纯数据操作，其消息/上下文持久化由 Node-RED 流程自行管理，不自动共享工作台变量。

## 各操作的语义

| 操作 | 行为 |
|---|---|
| 创建记录 | 按字段表输出一个结构体，保留数值/文本/开关/空值及嵌套类型 |
| 追加/去重 | 默认满表或键重复报错；可明确选择丢弃最早一行、忽略重复项或原位替换 |
| 筛选/排除 | 严格类型比较；数值 1、文本 1 和开关不是同一个值；存在与缺失比较区分空值 |
| 稳定排序 | 同类型数值/文本/开关排序；同值保留原相对顺序；缺失/空值可报错或固定置前/后 |
| 按行读取 | 索引从 0 起，-1 表示末行；越界默认报错，可选择返回 found=false 与空记录 |
| 字段映射 | 用输出名称/源路径表精简、重命名或展开字段，来源缺失时报错或跳过整行 |
| 数值统计 | 总和、均值、最小/最大、中位数、总体标准差；无有效值返回 hasValues=false 和空统计表 |

字段路径采用点分隔，可包含数组索引，如 `camera.pose.x`、`items.0.width`。不执行表达式或脚本。筛选的“比较值”在 `value` 字段里选择实际类型/绑定；存在、缺失及开关比较不使用比较值，但普通绑定解析仍遵守运行时规则。

筛选的“跳过缺字段”表示该行不进入结果，即使选择排除匹配行也一样。显式空值仍有字段，因此“字段存在”会匹配它；大小比较不会把空值/文本/开关转换为数值。统计可显式跳过空值/缺字段，但不会跳过类型错误。文本排序按字符顺序，不解析日期或地区排序规则。

去重键必须在所有已有记录及新记录中存在，且为非空标量。数值 1 与 1.0 是相同数值键，文本 1 和开关 true 是其他类型。已有记录出现重复键时拒绝继续追加，避免任意挑一条替换。已有表超过新容量时也会报错，不批量静默删行。忽略/替换重复项不触发满表丢弃。

统计结果为空时不要直接绑定不存在的均值字段，应先检查 hasValues。越界返回空记录时应检查 found。清空记录可使用现有变量赋值节点，把该变量赋为空数组；更改工程初始值不会覆盖已持久化的当前变量。

## 采样记录接手眼标定

“采样记录 → 满六组后手眼标定”演示每次读取一条预制合成姿态，加上 sampleId 后去重累积；字段映射提取手眼算子要求的十二列，再由条件分支控制满六组后执行拟合。前五轮只提交记录，第六至八轮恢复相机→工具平移 (30,-20,80) mm；第九轮索引越界且已提交的八条记录不变。

生产采样可把预制记录来源替换成“按字段创建记录”，分别绑定同步读取的机器人位姿和棋盘位姿字段，再追加及映射。机器人停止、图像稳定、单位/旋转约定、同一棋盘原点和采样同步仍需由实际流程保证；这些记录算子不移动机器人，也不提供联机采样向导。

另有两个演示：真实 OpenCV 计数后保留最近三条记录，并在 HMI 表格显示平均数量；筛选宽度至少 6 的记录，排序后得到 12、8、6，读取最大项并统计均值 26/3。

## 容量及证据

记录表最多 1000 行且编码数据不超过 500000 字节；单条新记录不超过 50000 字节。每个结构体最多 100 字段，嵌套深度、总元素数也有限制。保留键、点号字段名、非有限数值、超量数据和统计溢出拒绝执行。图像和大点云应继续走原数据通道，不作为采样记录存储。本功能不代替长期数据库或逐帧无损归档。

`npm run test:records` 覆盖十项 Python 类型/边界/去重/筛选/排序/统计测试，以及五项真实插件流程测试：五轮 OpenCV 累积、HMI 绑定、八轮条件采样与真实手眼求解、三级变量/回滚及 Node-RED 桥接。HTTP 验证七算子元数据、空白去重键表单、五轮采样、工程/HMI/记录保存、服务重启后继续采样和满表回滚。相关 75 项 Node 回归及语法检查通过。新增画面的可视验收与 Linux 运行仍未完成；手眼数据为合成数据，未计入实机精度验收。
