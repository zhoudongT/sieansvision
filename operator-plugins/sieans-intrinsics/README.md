# 相机内参与镜头畸变校正

`sieans-intrinsics` 1.0.0，MIT，沿用现有 OpenCV / NumPy / Pillow，无新增依赖。上游参考 [OpenCV GitHub 标定示例](https://github.com/opencv/opencv/blob/4.x/samples/python/calibrate.py) 和 [官方标定教程](https://docs.opencv.org/4.12.0/dc/dbb/tutorial_py_calibration.html)。插件通过现有工作台与 Node-RED 通用算子加载；全部配置采用表单、点位表和变量绑定。

## 实际采集流程

1. 固定相机分辨率、镜头焦距、对焦及图像裁剪方式。准备平整、尺寸已知的棋盘格，默认 **9×6 个内角点对应 10×7 个方格**。输入的是内角点数量和方格边长。
2. 定义流程变量 `calibrationPoints`，类型为数组，初始值为空数组。添加“棋盘格角点采集”，将“累计角点表”输入绑定到该变量，并将输出 `points` 绑定回该变量。
3. 输入相机图像或打开本机图片。视图编号从 1 开始，执行采集算子。图像中显示角点标注，结果表显示图像坐标及采集尺寸；标注不会进入下游图像通道。
4. 逐次改变棋盘倾角、位置和覆盖区域，保持相机成像设置不变，递增视图编号再执行。至少六个完整视图，建议 10–15 个、绕不同轴倾斜并覆盖边缘。重复拍摄同一姿态不能提供足够约束。采集失败保留上一轮已提交的点表。
5. 添加“相机内参标定”，绑定累计角点表，填写相同的行列、格边长、图像宽高和最大允许重投影误差。可以执行所选标定节点，避免重新执行采集节点并产生重复视图编号。
6. 将标定输出 `calibration` 绑定到流程或全局变量，例如 `cameraCalibration`。结果显示水平/垂直焦距、主点、五个畸变系数、总误差及逐视图误差表。
7. 在后续检测流程中，将“镜头畸变校正”的标定结果输入绑定到上述变量。输出校正图进入下游算法。采集与校正建议分别配置流程；不要每轮生产检测都重新标定。

重新采集整组数据时，可通过变量表将累计角点变量恢复为空数组。仅更改工程初始定义不会覆盖已经持久化的当前变量。当前没有独立的采集向导、图片批量导入或单视图移除按钮；点表可以通过表格编辑，删除视图时必须移除该视图全部角点。

## 模型与坐标

模型为零斜切针孔模型，含 fx/fy/cx/cy 与 OpenCV 五系数 k1/k2/p1/p2/k3，不是鱼眼、双目、手眼或机器人基坐标标定。角点表每行含视图编号、零起算列/行、图像 X/Y、采集宽/高，最多 1000 行。默认 54 点棋盘最多累计 18 个视图。不同分辨率、重复角点、缺失角点、重复采集编号、图像外坐标拒绝执行。

畸变校正保留原始图像尺寸和内参矩阵，不隐式裁剪或缩放；边缘无有效源像素时填黑，不保证完整保留原视野。校正算子的 `calibration` 输出适用于校正图，保留 fx/fy/cx/cy 并将畸变系数置零，避免后续重复校正；原始绑定变量不变。对同尺寸的其他相机或变化焦距仍不可直接复用，相同尺寸不能证明镜头设置相同。

校正后的图像坐标与原始畸变图不同。使用平面透视标定、卡尺、ROI、模板等时，应在校正图重新建立点位和模板，不可混用两种坐标。

## 质量及证据

采用多视图线性约束退化检查、有限值/参数范围校验以及总/逐视图重投影误差门限。低重投影误差只代表训练视图拟合程度，不能代替独立视图、已知尺寸和实际相机精度验收；不自动剔除坏视图，不声明完整物理可辨识性验证。棋盘平整度、角点质量及视野覆盖仍需现场确认。

演示菜单增加三项：合成棋盘角点采集、八视图内参求解、标定变量驱动图像校正。八视图点来自已知针孔投影（fx=710、fy=725），网格图仅用于展示校正行为；没有把它宣称为实拍畸变图。

`npm run test:intrinsics` 覆盖八项 Python 数值/拒绝测试、三项真实子进程运行时/变量累积/Node-RED 桥接测试，以及 HTTP 插件发现、工程点表保存、变量绑定、校正图通道、错误尺寸、服务重启及再次执行。相关运行时、插件、桥接、流程图和卡尺共 52 项回归通过，`npm run check` 通过。真实工业相机及 Linux 验收尚未完成。
