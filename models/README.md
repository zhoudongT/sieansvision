# 模型目录

放入可信的 YOLOv8 / YOLO11 目标检测权重（例如 `yolov8n.pt`、`yolo11n.pt`），或经 Ultralytics 导出的检测 ONNX 模型。

安装推理依赖：`python -m pip install -r vision/requirements-yolo.txt`。

节点只读取本目录中的模型，不自动下载。默认 CPU 推理。当前支持目标检测与实例分割，不包括分类、姿态或训练。自定义工业零件需要对应的数据集和训练权重；通用 COCO 权重不能代替缺陷模型。

Ultralytics 提供 AGPL-3.0 与商业许可，产品发布时需根据所采用的软件和模型许可选择发布方式： https://www.ultralytics.com/legal

## YOLOv8 / YOLO11 实例分割

工作台选择“缺陷与 AI → YOLO 实例分割”，Node-RED 节点为 `machine-yolo_segment`。分割只接受本地可信 `.pt` 权重；误用检测模型会报错。该节点固定 CPU 推理，不自动下载模型。依赖锁定为 `vision/requirements-yolo.txt` 中的 Ultralytics 8.4.177。

参数通过表单配置，类别编号通过数组表编辑。输出每个实例的类别、置信度、原图坐标中心、外接框、轮廓和像素面积。轮廓表保留空洞标记与父轮廓索引；轮廓简化不改变面积统计。ROI 之外的掩膜为黑色，坐标始终相对完整原图。

- **彩色叠加**：显示标记图，下游继续收到原图。
- **二值掩膜**：下游收到无损 PNG 二值掩膜，可继续连接几何或测量节点；Node-RED 输出 1 的图像通道同步更新。
- 掩膜并集面积消除实例重叠，实例面积之和保留重叠；两者不可互换。面积是还原到原图后的非零像素计数，与几何轮廓积分面积不同。未经标定不能当作实际面积。
- 未检出目标或全部被面积筛选排除时返回零目标、全黑掩膜；达到最大目标数时结果提示上限，不宣称已经检出全部目标。
- 推理尺寸为 32–1280 的 32 倍数，最多 100 个目标，目标数 × 推理尺寸平方不超过 32768000；总轮廓点数不超过 50000。超限报错，不静默截断轮廓。掩膜逐个还原，避免同时存放全部全分辨率掩膜。
- 历史记录默认保留数值和轮廓；仅启用“保留数据帧”后保存掩膜图片。

演示案例的“AI 分割”分类含 YOLOv8 轮廓面积与 YOLO11 掩膜测量两个流程。后者筛选 COCO 类别 5（公交车），写入整数变量 `maskAreaPixels`。公共场景示例用于验证软件链路，工业工件/缺陷仍需训练权重及现场验收。

本机验证权重来自 [Ultralytics 官方模型资源](https://github.com/ultralytics/assets/releases/tag/v8.4.0)，不包含在既有源码发布包内：

## 通用模型训练模块（2026-10-16）

工作台顶部“模型训练”提供目标检测/实例分割的通用训练入口，不绑定具体工件。表单配置训练任务、类别、基础权重、轮次、尺寸、批量、学习率与种子；类别、数据检查、任务和指标使用表格展示，后台配置不要求用户编辑 JSON/YAML。

没有实际工件时，创建“合成示例”：12 张训练图片、4 张独立验证图片，单一 part 类别、随机背景与矩形零件。根据所选任务生成框或多边形标注。示例仅验证软件训练链路，指标不能作为工业检测精度。没有自动启动或下载数据集。

使用自己的数据时：创建空数据集，按页面显示的服务器目录放入 images/train、images/val、labels/train、labels/val。同名图像与标注一一对应；支持 JPG/JPEG/PNG/BMP，目录不递归。检测标注为类别编号及归一化中心 X/Y、宽、高；分割为类别编号及归一化多边形点坐标，至少 3 点。背景图需提供空标注文件。类别按表格中从零开始的编号填写。可使用“图片导入与标注”绘制和修改目标；当前不包含自动划分或 ZIP 上传。

开始训练前及复制快照后检查图片解码、大小、标注缺失、类别、归一化范围、检测框边界、分割零面积和重复图片内容（包括训练/验证泄漏）。每个划分至少一张含目标图片。每张不超过 12 MB/1600 万像素，每个划分最多 20000 张，每张最多 1000 个目标。任务目录保存数据快照及指纹，原始数据集编辑不会改变已建立的训练快照。

训练支持 CPU、自动选择和指定 CUDA 显卡；AdamW、workers=0、AMP 关闭，使用 Ultralytics 8.4.177 和本地可信 .pt 权重。CUDA 环境及验证见下文。支持 1–300 轮、64–640 的 32 倍数训练尺寸、1–8 批量；最长 6 小时。单任务与工作台运行时互斥。关闭训练窗口或浏览器不停止任务；“停止训练”终止子进程树，任务结束后释放运行锁。服务正常退出停止训练，异常父进程消失时子进程自行退出；重启后将未完成记录标记为中断，不自动续训。

首轮训练/验证完成后显示训练损失、验证损失、精确率、召回率与 mAP 等指标；后台最新任务、指标、设置和产物写入独立数据目录 training 下。页面展示当前/最近任务，不包含多任务历史管理或断点续训。完整成功后可将 best.pt 以 trained- 开头的新文件名安装到模型目录，核对 SHA-256，不覆盖同名文件。点击“添加为流程算子”按任务类型加入目标检测或实例分割节点，再连接自己的输入图片验证；模型也可由现有 Node-RED 节点使用。

验收：`npm run test:training`。包括 4 项数据检查测试、HTTP 创建/检查、检测与分割各真实训练 1 轮、损失与指标、运行锁互斥、权重校验及重新推理、任务不匹配、运行中取消与取消模型禁止安装。功能采用[Ultralytics 官方训练接口](https://docs.ultralytics.com/modes/train/)与[GitHub 训练器实现](https://github.com/ultralytics/ultralytics/blob/main/ultralytics/engine/trainer.py)，许可说明沿用本页上文。

## 图像导入与交互标注（2026-10-16）

入口为“模型训练 → 选择数据集 → 图片导入与标注”。选择训练集或验证集后可批量导入 JPG/PNG/BMP（每批最多 100 张、每张 12 MB/1600 万像素）；同名文件不覆盖，两个划分中已存在的相同文件内容会拒绝导入。新图片保留“待标注”状态，只有明确保存标注或点击“保存为背景”后才生成标注文件，避免将未处理图片自动当作背景。

目标检测在图片上拖动绘制矩形；实例分割逐点点击后按 Enter 或“完成轮廓”闭合。使用“选择 / 移动 / 调整顶点”移动整个目标或拖动角点/轮廓顶点；类别和像素坐标均可在右侧表格修改。支持删除目标、最多 30 步撤销和放弃本张未保存修改。切换图片、数据划分或关闭时，未保存修改会阻止操作并提示先保存或放弃；Esc 取消当前绘制。列表分 50 张追加显示。

分割采用单个简单多边形，每个轮廓最多 500 点，拒绝越界、重复顶点、零面积、自相交/相切；不包含带洞轮廓标注；模型辅助标注见下文。标注在后台转为 YOLO 归一化格式，图片和表格使用原图坐标；预览最长边最多 1600 像素，不改变原始训练图片。两种划分仍需人工选择，尚无拖动移组/自动划分功能。

保存会校验图片和标注的内容版本，过期页面提交返回冲突，避免覆盖另一页面修改。覆盖前将旧标注保存到数据集 annotation-history 下，可从文件恢复；可在“标注历史”中载入旧版本，确认后再保存。标注操作和训练均使用运行锁；保存后可直接回到训练页面检查数据并启动训练，不需要手写配置。

验收仍使用 `npm run test:training`：4 项原数据检查、6 项标注读写/冲突/备份/背景/导入/无效多边形/路径测试、3 项绘图几何测试，以及检测/分割编辑标注后的真实训练、指标、权重安装和推理验证。另经浏览器验证实际轮廓点击绘制、顶点拖动、未保存保护、图片导入及显式保存背景。


## CPU / CUDA 计算设备（2026-10-16）

YOLO 目标检测、实例分割和模型训练均提供设备表单：CPU（默认）、自动选择、实际检测出的 CUDA 显卡。训练窗口的“计算设备”和算子参数的“查看计算设备”以表格列出 PyTorch、CUDA 运行库、显卡名称、显存和计算能力。结果与训练任务记录实际设备、请求设备和选择原因。

自动选择在 CUDA 不可用时选择 CPU 并记录原因；显式指定不可用显卡直接报错。推理检查后端实际设备，显存不足或设备不匹配不静默重试 CPU。ONNX 的 CUDA 还需要 CUDAExecutionProvider；本机仅验证了 .pt 的 CUDA 推理，未认证 ONNX GPU。训练维持 FP32，默认设置 CUBLAS_WORKSPACE_CONFIG=:4096:8 以支持确定性 CUDA 运算。

可选安装配置 `vision/requirements-cuda.txt` 固定 torch 2.11.0+cu128 / torchvision 0.26.0+cu128，从 PyTorch 官方 cu128 索引取得。部署安装可选 `--features cuda`（自动包含 2d、yolo），部署 doctor 同时检查依赖版本和显卡可用性。建议使用独立 GPU Python 环境，通过 VISION_PYTHON 或部署 configure --python 指定；CPU 部署无需安装 CUDA 包。Linux 尚待实机验收。

本机 .venv-gpu 为独立 CUDA 包环境，其 sieans-shared.pth 引用本机 .venv 的其他依赖，仅作开发验证，不能复制到另一台机器部署。新部署应使用 requirements-cuda.txt 完整安装依赖。

验收 `npm run test:gpu`（可用 VISION_GPU_PYTHON 指定解释器）：Windows、RTX 3060 Laptop GPU 6 GB、驱动 592.27、CUDA 12.8。覆盖设备校验、显存不足不重试、YOLOv8/YOLO11 的 CPU/CUDA 切换与检测一致性、分割掩膜一致性、设备查询 HTTP、Node-RED 分割链路、检测/分割真实训练及权重安装后 CUDA 推理、取消任务释放运行锁。训练和推理使用合成/公开演示图片，不代表实际工件精度；首次加载耗时不作为性能基准。


## 模型辅助标注（2026-10-16）

入口“模型训练 → 图片导入与标注 → 模型辅助标注”。对当前图片选择本地可信 .pt 模型、CPU/自动/CUDA 设备和 0.01–1 的最低置信度，点击“生成候选”。模型任务必须与数据集检测/分割任务相符，不自动下载权重。一次最多 50 个候选，达到上限会提示可能遗漏；超过 2 分钟终止。使用原始图片推理，坐标按原图归一化，与最长边 1600 像素的预览缩放无关。

候选表展示模型类别、置信度、采用开关和数据集类别。只有类别名称完全一致时自动映射并勾选；未知名称必须人工选择数据集类别，模型类别编号不会直接当作数据集编号。生成候选不写标注文件，也不修改当前目标。点击“采用所选候选”追加到本张未保存目标，可继续移动、修改坐标或类别、删除和撤销；不会替换已有目标。候选采用后清空，避免重复采用。最终仍需明确点击“保存标注”；零目标不会自动保存为背景。

当前标注格式仅支持单个简单多边形。分割掩膜含孔洞、多块分离轮廓、超过 500 点或转换后几何无效时，目标进入“需人工绘制”表，不会自动填洞、跨区域连接或保存错误轮廓。候选生成前后检查原图/标注内容版本，过期返回冲突；保存仍采用既有版本校验与旧标注备份。生成期间使用训练模块的运行锁，并冻结编辑与切图操作。当前仅单张人工辅助，没有无人值守批量标注、跨图片自动传播或精度承诺。

验收：npm run test:training 包含新增 3 项候选转换/真实模型测试及真实 HTTP 检测、分割、只读生成、类别重映射、显式保存、版本冲突和模型路径/任务检查。CUDA HTTP 验收也在本机 RTX 3060 上运行；浏览器验证了 GPU 候选、未知类别拦截、采用/撤销和保存。


## 标注历史恢复（2026-10-16）

图片标注窗口的“标注历史”展示当前图片的旧版本时间、目标数量、状态和载入按钮。最多展示最近 200 个备份，更多文件仍保留在服务器。背景标注作为零目标版本保留；损坏、超过大小上限或不符合当前类别/几何格式的历史列出原因并禁止载入。

历史读取不写入文件。载入到编辑器后显示未保存状态，可以修改、撤销或放弃；明确点击“保存标注”（空版本使用“保存为背景”）才完成恢复，同时备份被替换的当前版本。因此恢复操作也可再次从历史取回。未保存修改会阻止打开历史；读取与保存检查当前图像/标注版本，防止旧页面覆盖其他页面修改。版本编号与路径由服务器验证，不能读取任意文件；当前没有自动清理备份或跨图片恢复功能。

新增两项 Python 测试覆盖只读历史、显式恢复、背景备份、版本冲突、非法编号、损坏几何和 200 项上限。HTTP 对检测/分割分别验证原标注→背景→读取旧版本（当前文件保持背景）→明确保存恢复，以及过期恢复冲突。浏览器验证了三目标→背景→历史载入→撤销→重新载入保存。
