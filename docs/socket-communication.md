# TCP / UDP 报文通信

工作台“工业通信”分类增加 TCP 报文通信、UDP 报文通信两个流程块；Node-RED 提供 `machine-tcp_exchange`、`machine-udp_exchange`。使用现有 Node.js 运行时的 `node:net`、`node:dgram`，无需另装通信包。源码与许可证来自 [Node.js 官方 GitHub](https://github.com/nodejs/node)；接口依据 [TCP 文档](https://nodejs.org/api/net.html) 和 [UDP 文档](https://nodejs.org/api/dgram.html)。当前验证环境为 Windows、Node.js 24.12.0；未完成 Linux 与现场设备验收。

## 操作与表单

三种方式：发送并等待应答、仅发送、仅接收。主机、端口、超时、报文格式按功能显示。发送内容为 UTF-8 文本、结构化字段或字节数组，通过表单/表格配置，也可绑定上游结果、全局/流程/模块变量。结构化格式使用 UTF-8 JSON 在线路上编码，界面展示字段和记录表。

每次执行单独建立并关闭连接，返回一帧/一个数据报；无自动重试和重连。总超时 100–60000 ms，包含本机模拟器启动、DNS、连接、发送和接收。最多 8 个并发事务；相同协议、配置主机及端口（UDP 还包括本地地址/端口）不能同时执行。这个锁按配置文本识别，不代表识别出主机名别名指向同一物理设备。

仅发送成功表示交给本地网络栈，`delivery=sent`，不表示设备已执行。请求应答/仅接收成功表示收到完整报文，`delivery=received`，不会冒充设备业务确认（`acknowledged=false`）。业务确认码、事务编号由后续条件/脚本节点检查。发送后的超时、失败、取消无法撤销外部动作；失败回滚的是平台变量。

## TCP 分帧

TCP 是字节流，不能用一次 data 事件当作设备报文。发送与接收分帧分别配置：

| 规则 | 发送 | 接收 |
|---|---|---|
| LF / CRLF / 零字节 | 自动添加结束符；内容内含该结束符则拒绝 | 跨数据段查找结束符，并从输出中移除 |
| 2 / 4 字节长度，大端或小端 | 添加无符号内容字节长度，长度不含头部自身 | 先拼接完整长度头，再读取指定字节数；超限长度立即拒绝 |
| 原始字节 / 固定字节数 | 原样发送 | 累积到应答字节数完成；不根据字符数计算 |
| 对端结束发送 | 发送完后结束本端写入，继续读取 | 以对端 FIN 为完成；未结束则等到总超时 |

UTF-8 解码在完整报文形成后进行，支持一个中文字符被网络拆开。不完整的结束符/长度头/定长报文遇到对端关闭时明确报错。无效 UTF-8 或无效结构化内容报错，可改用字节数组查看二进制协议。内容与接收上限为 64 KiB；2 字节长度头最多 65535 字节。

仅接收仍由平台主动连接远端 TCP 服务，不是 TCP 监听服务器。每次只取首帧，关闭连接时其余数据不保留；`trailingBytes` 只统计首帧完成时**已经到达当前缓冲区**的尾随字节，未来才到达的字节无法计入。需要连续多帧、共享长连接或设备主动连接的平台服务仍待实现。

## UDP 对端与本地端口

每次最多发送 65507 字节；接收一个数据报，不把多个数据报拼接。仅接收要求指定本地端口；请求应答和仅发送可用 0 自动分配。可选本地 IP，须与解析后的远端 IP 地址族一致。主机名使用系统解析的一条地址；连接到明确远端地址/端口，并核对收到报文的来源，不接受任意来源的报文。

UDP 的关联不检查设备是否在线。UDP 不保证送达、顺序、不重复，来源筛选也不是身份认证。当前不支持广播、组播、设备主动发现或事务编号自动匹配；应用协议可在内容中定义编号，由条件/脚本校验。仅接收期间该本地端口归当前任务独占，取消/完成后释放。

本组节点为普通 TCP/UDP，不提供 TLS/DTLS；加密 MQTT 已有独立节点。串口通用报文、长期监听、设备事件触发仍属后续范围。

## 演示与验证

工业通信面板可启动/停止绑定 `127.0.0.1` 动态端口的 TCP/UDP 原样回显设备。选“本机模拟设备”会自动启动；运行任务期间不能停止。重启会清空接收字节统计。

“演示案例 → 通信”提供四个可运行案例：

1. 视觉检测 → TCP → 流程变量：真实轮廓检测输出 3，经长度前缀报文回显后写入 `networkReply`。
2. TCP 扫码文本：CRLF 分帧，保存 `SIEANS-A-00042`。
3. UDP 检测记录：发送编号、判定和两条带单位的测量记录，按字段表显示。
4. UDP 二进制：8 个字节，其中包括 0 和 255。

`npm run test:socket` 覆盖真实套接字、分段中文/头部/结束符、粘包首帧、EOF、定长、畸形/超限数据、来源筛选、端口冲突、取消和超时、变量类型和回滚；HTTP 验证认证、四个演示、工程保存、历史归档、取消与模拟器运行锁；实际 Node-RED 部署 TCP → UDP 链路验证消息/常量输入与 Catch 错误。Node-RED 参数编辑器由 `node scripts/build-socket-editor.cjs` 生成，`npm run check` 检查与工作台定义一致。

上述验证使用本机模拟服务，不等同于扫码枪、PLC 或测量设备的现场协议验收。
