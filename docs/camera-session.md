# 连续相机连接与单帧缓存

新增服务器持有的相机会话，SDK 连接和采集管线跨帧复用。沿用 [Harvesters 官方采集接口](https://github.com/genicam/harvesters/blob/master/docs/TUTORIAL.rst) 和 [OpenCV VideoCapture](https://docs.opencv.org/4.10.0/d8/dfe/classcv_1_1VideoCapture.html)，没有新增外部依赖。该服务与工程连续检测独立：相机持续产生帧，工程通过取帧节点获取图像；它不会自动为每一帧启动工程。

## 使用方法

1. 打开“相机设备”，枚举并选择设备。在所选相机采集节点中配置分辨率、曝光或深度参数，然后打开相机管理；同一驱动、设备及 GenTL 驱动编号匹配时，连续会话沿用该节点参数，否则使用所选设备默认参数。
2. 在“连续连接与帧缓存”设置最短采集间隔、重连次数和等待时间，点击“打开所选相机并持续采集”。仅支持自由采集，软件/外部触发配置会被拒绝；这些触发仍使用原单帧节点。
3. 状态变为“持续采集中”后，可以预览最新缓存帧，或点击“添加连续取帧节点”。节点自动填写当前会话编号，默认等待请求之后到达的新帧。连接下游 2D/3D 检测算子，可用现有“连续检测”反复运行完整工程。
4. 参数面板可选择“等待下一帧”或“最新未过期缓存帧”。后者显式配置最大帧龄，并可能重复返回同一缓存帧；结果表显示帧序号、缓存帧龄、读取策略和是否重复。
5. 先停止工程，再在相机管理点击“停止并释放设备”。关闭浏览器或对话框不停止相机。其他工作台客户端可以查看和停止同一服务器会话。

服务重启不自动打开设备、不恢复图像缓存。已保存工程中的会话编号随新连接变化；重新连接后应重新填写当前编号，或重新添加取帧节点再连接流程。可以使用“按上次配置重新连接”，它仍需明确点击。生产工程宜将会话编号绑定到统一流程/全局变量，更新时通过变量表维护。

演示菜单中的“连续相机连接 · 新帧取图与数量检测”只打开内置模拟相机，自动填写会话编号，检测三个目标。再次运行或连续检测时帧序号递增。演示保持连接，停止入口在相机管理；已有其他设备的会话时拒绝替换。

## 连接、缓存与故障语义

- 支持现有 UVC、GenTL 2D/XYZ、RealSense、Orbbec 适配器及两类模拟相机。UVC 使用一个 VideoCapture；GenTL 使用一个 Harvester/ImageAcquirer，参数设置和 start 仅在建连时执行，每帧 fetch 的缓冲区在返回前复制并归还；RGB-D 使用一个 SDK Pipeline。预热只在初次建连或重连执行，原单帧接口保持采集后释放。
- 当前服务器最多一个连续会话。与单帧操作共用资源锁；所有物理后端保守共享一个锁，模拟设备共享另一个锁。连接保持期间，同类设备的单帧打开/枚举会被拒绝。运行工程时禁止从工作台打开或停止连续会话，避免改变在用输入。
- 服务器只保留一个已验证完整帧，新帧覆盖未取的旧帧，覆盖次数可见；它不是逐帧无损队列。SDK/设备内部缓存与传输链路丢帧不包含在此计数中。`next` 指请求后服务器收到的新帧，**不能保证曝光发生在请求之后**；相机或驱动可能有内部缓冲。帧龄按服务器收到并解析的时间计算，不是曝光年龄。
- 输出继续遵守图像/深度/点云通道：2D 帧清除旧深度/点云，RGB-D 保留 png16 原始深度、尺度、内参及毫米点云；GenTL XYZ 沿用轴比例/单位验证。单帧最大 35 MB，现有图像及点云数量限制仍生效。传输采用管道背压，采集间隔最少 50 ms；不承诺高帧率实时性能。
- 只允许一个等待新帧的消费者；同时等待返回占用错误。缓存预览也算一次读取，会影响取帧/重复/覆盖统计。等待超时或取消只取消该读取，后台连接保持；停止或失败会清空缓存并拒绝等待者，不用旧帧填补失败。
- 重连默认关闭，可配置本次会话总计最多五次、每次 200–60000 ms 等待。短暂恢复不会重置次数；重连会重新枚举、打开设备及应用参数。断开时清空缓存，重连成功后的帧序号继续增加。SDK 进程无响应则由服务器超时结束会话，**不会自动重开**。没有真实设备断线恢复或长期压力验收。
- 正常停止经 stdin 请求，让 SDK 在当前读取结束后 stop/release；超出采集超时加两秒则结束自有子进程。强制结束时不能保证 SDK 的 finally 执行，也不保证设备参数恢复。已应用的曝光、触发模式或流配置不会回滚。服务停止时先取消工程等待，再释放相机；未提交变量保持回滚。
- 配置及状态概要保存在独立运行目录。约五秒或状态变化时记录统计，异常退出可能缺少最近统计；帧数据和待取请求不落盘。发现未正常停止的记录标记“服务中断”，不自动恢复采集。

## Node-RED 与验证

集成版“相机采集”节点增加“已连接连续相机”驱动、会话编号、取帧策略、最大帧龄和超时表单，也可通过 `msg.cameraParams` 传递这些参数。输出仍为 `msg.image/cloud/depth/camera`，不暴露后端配置数据编辑器。关闭节点取消其等待，不关闭其他流程可复用的会话。

`npm run test:camera-session`：五项 Python 连接/预热/缓冲/释放测试，覆盖 UVC、GenTL 2D/XYZ、RealSense 与 Orbbec 的受控 SDK 生命周期；七项 Node 专项使用真实 Python 持续进程验证帧递增、缓存覆盖、过期拒绝、超时/取消、设备互斥、有界失败重连、RGB-D、多轮真实 OpenCV 及 Node-RED 节点。认证 HTTP 验证跨客户端操作、运行互斥、工程保存、停止释放、等待作业回滚和服务重启。另有 61 项相关 Node 回归及 41 项相机 Python 回归通过，语法检查通过。

Windows 原生工业相机/CTI、深度相机实物、网络断线及长期吞吐、Linux 尚未验收。海康/大华设备需要其兼容 CTI/GenTL Producer，或另做厂商 SDK 插件；不能将 SDK 生命周期模拟视为这些品牌已经完成实机接入。当前桌面自动化通道不可用，新增界面的视觉验收未计入通过项。
