# 服务器连续检测

工作台“连续检测”提供轮次间隔、执行次数表单，以及运行统计表。调度位于 Node 服务器；浏览器只负责启动、监控和停止，刷新或关闭页面不结束任务。当前单台服务器同一时刻只运行一个工作台作业或连续检测会话。

## 使用

1. 配置并单次验证工程。可先运行“组态运行画面 · 相机数量检测”模拟演示。
2. 点击“连续检测”，填写轮次间隔（100–3600000 ms）和执行次数（1–1000000；0 为直到停止）。默认 1000 ms、10 轮。
3. 点击“启动连续检测”。含 Python 脚本的工程需要先勾选工作台的可信脚本执行开关。服务器使用启动时的完整工程、输入图像/点云快照。
4. 相机节点每轮重新单帧采集。文件图像/点云每轮复用启动时的数据；不会自动监控文件目录或更换文件。
5. 通过状态条、运行详情和 HMI 查看最近一轮。刷新或从另一已认证浏览器打开后，点击“运行详情 → 查看运行工程”加载服务器的配置快照，再进入运行模式。
6. 工具栏“停止”、状态条“停止连续检测”、详情“停止本次连续检测”和 HMI 的停止按钮都能结束会话。轮次间隔中停止立即取消后续计划；执行中停止先取消本轮，再释放运行资源。

“查看运行工程”仅载入服务器内存中的工程配置，不会覆盖磁盘上的已保存工程，也不会复制另一浏览器原先打开的输入文件。停止后若要重新启动文件流程，应重新打开输入文件。相机流程可重新采集。页面未加载当前工程时，状态条仍显示实际运行工程名称，避免把另一个工程误认为正在运行。

## 执行语义

每一轮都是完整作业，遵守图依赖、分支、变量事务和插件版本检查。上一轮彻底完成后再等待设定间隔，不追赶错过的时间、不重叠启动。因此实际周期为本轮执行时间加间隔，不是相机硬件帧率或硬实时周期。

执行成功轮次表示流程没有执行错误，不代表产品合格。算子返回 `passed=false` 时，流程仍可执行成功；产品统计、剔除或复检应通过条件节点与变量实现。执行错误会停止连续检测，不自动重试相机触发或设备写入。

每轮成功后单独提交变量；失败或取消仅回滚该轮变量，之前成功轮次保留。已经发出的设备动作不会随变量回滚。取消视觉算法时，当前不可中断的计算可能需要完成后才停止；脚本、通信和相机适配器沿用各自的取消/超时机制。

运行锁覆盖轮次间隔：工作台拒绝其他单次/连续作业、变量写入、插件启停、工程保存、相机和工业设备的手动访问。浏览器锁定工程编辑和 HMI 输入。停止可由其他具有现有工作台访问权限的客户端请求；请求携带会话 ID，旧页面的过期停止请求不能停止新会话。

此锁属于 SIEANS 工作台运行时。独立 Node-RED 部署的流程和外部程序不是该调度器的一部分，不能据此认定所有厂商 SDK/PLC 客户端都已统一互斥。设备长连接、高帧率流采集、硬件触发同步、排队多工程仍待实现。

## 数据与重启

最近会话摘要写入数据目录 `continuous-run.json`，包含工程标识、时间、设定次数、开始/完成/失败/取消计数及错误，不写入工程代码、输入图像和点云。启动与轮次结束时保存摘要；进程突然退出时最后一轮计数可能尚未写入。

服务重启时，摘要中未结束的会话标记“已中断”，不会自动重新触发设备或补做轮次。重启后重新打开保存的工程和需要的文件，检查现场状态后手动启动。当前不是作业恢复或“恰好执行一次”机制。

实时视图仍只缓存最近 3 个作业；已结束的作业另外写入持久化历史，见下节。变量按原规则持久化。其他页面约每 750 ms 轮询状态，可能跳过短周期的中间帧，统计仍由服务器累计。

## 运行历史归档

工具栏“运行历史”提供当前工程/全部工程、执行完成/失败/取消、起止时间筛选，每页 20 条。点击“查看明细”，可选择本次工程中的任一模块，区分已完成、失败、跳过、未执行和未纳入单步范围。参数、嵌套结果、变量快照使用表格，脚本代码只读展示，不需要编辑 JSON。查看历史不替换当前工程，不执行历史脚本，不恢复旧变量。

默认归档工程快照（含参数、代码、参考图/参考点云）、本次计划节点、节点结果/错误/日志、起止时间和结束时的已保存变量。成功记录显示提交后的变量；失败/取消记录保留执行过程结果，但变量快照为回滚后已保存值。预检拒绝的请求还未创建作业，因此没有运行记录。“执行完成”并非产品合格；列表仅统计模块结果顶层 `passed === false` 的数量，不代替工程的最终质量判定。

在“当前工程的归档设置”勾选保留图像、深度和点云，后续新启动的作业会额外保存输入数据帧及每个节点输出数据帧；应用后保存工程以保留该选项。连续检测沿用启动时的工程快照。图像可在明细查看，点云展示单位、点数及前 50 点坐标表，深度展示尺寸、内参和已有的距离伪彩预览；当前历史界面没有独立的三维交互视口。默认关闭此选项仍会保存工程参考数据及算子结果中主动返回的数据，不应将其理解为删除所有图像相关参数。

历史保存在数据目录 `run-history/`。每个作业使用 UUID，明细与摘要分别通过临时文件加重命名写入；摘要含明细字节数与 SHA-256。读取明细时校验大小和摘要，损坏记录不会作为正常结果返回。重启时会从完整明细恢复缺失/损坏摘要；无法恢复的文件保留并显示诊断。校验用于发现文件损坏，不是签名或防篡改审计。

默认按开始时间保留最近 200 条，有效明细合计不超过 256 MiB，每条不超过 50 MiB。新归档与启动恢复时清理超限的最旧有效记录；摘要、临时文件和无法恢复的文件不包含在有效明细容量内，异常文件需管理员处理。当前没有通过界面修改全局保留策略或长期数据库归档的功能。

归档结束前运行锁保持占用。归档失败会显示于作业查询、工作台日志/状态和 HMI；执行成功并已提交的变量不会因归档失败撤销。连续检测在归档失败后停止后续轮次，以免继续产生无法追溯的结果。服务被强制终止时尚未完成的作业可能没有明细；本功能不实现中断作业恢复、设备动作补偿或断电级持久化保证。

HTTP 接口沿用工作台鉴权：`GET /api/vision/history` 接受 `projectId`、`state`、`after` / `before`（开始时间的毫秒时间戳）、`offset`、`limit`；`GET /api/vision/history/:id` 返回只读完整记录。日期筛选使用开始时间，两端包含端点。该归档仅覆盖工作台 Runtime 的手动与连续作业，不包含独立 Node-RED 节点执行和单算子调试接口。

验证：`npm run test:history` 包括 11 项存储/运行时测试及独立 HTTP 测试。覆盖工程/变量/日志快照、数据帧开关、失败/取消回滚、单步范围、实时缓存淘汰、并发归档、条数/容量保留、启动清理、连续轮次、损坏/路径拒绝、存储失败停止调度；HTTP 使用真实图像算子和 Python，检查鉴权、工程设置保存、筛选、重启查询和损坏返回。浏览器实际验证缺陷记录、错误赋值记录、状态筛选、未执行模块、回滚值和留存图像。

## 验证

- `npm run test:continuous`：9 项调度测试，涵盖不重叠、跨轮事务、间隔期锁、立即停止、执行中取消、首个异常停机、快照隔离、旧会话停止拒绝、重启摘要与存储失败释放锁。
- `npm test`：59 项 Node、23 项 Python 测试以及 HTTP/Node-RED 集成。HTTP 实际运行模拟相机→轮廓检测→变量计数三轮；检查跨客户端视图、间隔期锁和停止摘要。
- 浏览器：有限 3 轮自动结束；不限轮次运行中刷新页面，加载运行工程并看到继续增加的计数；从第二客户端停止，在 26 轮处结束，原客户端同步恢复输入和按钮。另以 5000 ms、5 轮验证刷新后的设置回读，并由 HMI 停止按钮在第 2 轮后结束。

上述相机测试使用模拟适配器；工业/体积相机实拍、PLC 现场和 Linux 实机验收仍待完成。
