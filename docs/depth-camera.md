# RGB-D 深度采集与 3D 检测

当前加入 RealSense 单帧适配器和明确标记的标定深度模拟器。使用官方 [librealsense](https://github.com/realsenseai/librealsense) Python SDK `pyrealsense2==2.59.1.11053`；发行包许可证与元数据留存在 `third_party/pyrealsense2/`。本机 Windows Python 3.12 已安装，SDK 枚举未发现 RealSense 实物。软件设备测试和模拟演示不代表实机采集验收或 Linux 部署验收。

## 安装与使用

在现有 Python 虚拟环境内执行：

```powershell
.venv/Scripts/python.exe -m pip install -r cameras/requirements-depth.txt
```

Linux 使用对应的 `.venv/bin/python`，并按官方 SDK 文档安装适合设备的系统支持和 USB 权限规则。SDK 为可选依赖；没有它仍可使用模拟深度、USB UVC 和 GenTL 适配器。

工作台“相机设备”选择 RealSense → 枚举 → 选择序列号 → 读取设备参数，可查看流格式、分辨率、帧率及深度比例。枚举不采集；读取参数不启动流。预览和流程采集才打开设备，单帧完成后释放。

添加采集节点后，表单设置深度尺寸、帧率、预热帧数、总超时、是否采集彩色、彩色尺寸、点云采样步长、最近/最远深度。默认深度和彩色 640 × 480、30 fps、预热 5 帧；必须是设备实际支持的组合，不自动替换成其他配置。不支持彩色的设备需取消彩色采集。采集按序列号定位，设备不见或不唯一时报错，不自动改用别的相机。此版本只支持自由采集，没有实现同步触发、连续流和断线重连。

## 数据、单位和坐标

- 原始深度：16 位单通道 PNG，无损保留 Z16 数值，0 为无效值。真实深度（米）= 原始值 × 设备报告的 `scaleMeters`，不假定所有设备都为 1 mm/单位。
- 点云：通过 SDK 根据设备内参与畸变模型生成，再从米换算为平台的毫米坐标。光学坐标 X 向右、Y 向下、Z 向前。数据包含单位、坐标系、内参和接收时间。
- 彩色：用 SDK 深度到彩色的纹理坐标映射为点着色。彩色视场外的有效深度点保留为灰色，不因无颜色而删除。不把两幅图简单缩放当作对齐；原始彩色与深度栅格没有对齐。内外参和两路设备时间戳/时钟域在结果表中展示，不能据此声称多相机或硬件曝光同步。
- 深度到彩色外参的平移单位仍为米，并在元数据中明确标注。SDK 列优先旋转数据转换为二维行列矩阵后保存。
- “深度图”标签是固定距离区间的伪彩色预览；黑色表示无效或显示区间外。改变显示范围/采样不会改写原始 16 位深度。测量使用点云坐标，不使用预览颜色。
- 采样步长按二维像素网格抽样；距离过滤使用米。深度最多 400 万像素，采样候选网格最多 20 万点；超限明确拒绝，不自动扩大步长。范围内没有有效采样点也会失败。分辨率、原始图、彩色和点云还受现有传输/作业大小上限约束。

官方坐标和投影依据：[Projection in RealSense SDK 2.0](https://github.com/realsenseai/librealsense/wiki/Projection-in-RealSense-SDK-2.0)，[Python 点云示例](https://github.com/realsenseai/librealsense/blob/master/wrappers/python/examples/opencv_pointcloud_viewer.py)。

## 流程与脚本

采集节点输出图像、原始深度与点云三个数据通道。3D 算子处理点云；Python 脚本用 `ctx["depth"]` 读取原始深度对象，通过 `image` 解码 PNG16，用 `scaleMeters` 换算距离，`intrinsics` 获取内参。脚本省略返回 `depth` 时沿用输入，返回空值时清除；返回替代数据时校验格式、位深、尺寸和内参。工作台变量和结果使用表格，无需直接编辑传输格式。

分支汇合沿用所选输入来源的整帧数据，避免把另一台相机的深度混入当前图像。下游滤波或测量保留采集原始深度；3D 裁剪不修改原始深度图。重新通过 2D 相机采集会清除先前深度和点云。

Node-RED 的 `machine-camera_capture` 使用相同驱动参数表，输出 `msg.image`、`msg.depth`、`msg.cloud`，元数据放在 `msg.camera` 与 `msg.payload`。3D 滤波/测量节点保留 `msg.depth`。错误交给 Catch；采集取消或超时终止本次 SDK 子进程。

## 演示与证据

“演示案例 → 采集 → 深度相机 → 点云裁剪 → 尺寸测量”：固定 64 × 48 RGB-D 场景，背景深度 1000 mm、顶面 975 mm，一处无效像素；有效点 3071。裁剪 970–980 mm 后为 200 点，尺寸 185.25 × 87.75 mm，Z 跨度为 0，写入流程变量 `topWidth=185.25`。这是采样可见顶面的包围尺寸，不是完整物体长宽高或实体体积。

`npm run test:depth` 包括 7 项 Python 测试、4 项运行时测试及隔离 HTTP/Node-RED 集成。覆盖实际 SDK 软件传感器投影、深度比例、PNG16 保真、纹理视场边界、采样/距离过滤、无设备拒绝、异常释放、真实 Open3D 裁剪测量、Python 原始深度读取、2D 重采集清理、分支来源选择，以及工程保存和变量绑定。硬件正确性、现场精度、Linux、Orbbec 与其他厂商深度相机仍需继续实现或验证。
## 原始深度文件入口

无设备时可用 [PNG16 文件导入](depth-file-import.md) 填写针孔内参与深度比例生成点云。适用于已校正的光轴 Z 深度，不把伪彩图当深度；原始值独立保留，可继续执行 3D 检测。此入口不代替厂商 SDK 或真实设备标定。
