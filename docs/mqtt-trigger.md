# MQTT 持续订阅与消息触发

平台沿用官方 [MQTT.js](https://github.com/mqttjs/MQTT.js) 客户端，实现服务器持有的长期订阅；本机验证使用 [Aedes](https://github.com/moscajs/aedes)。无需增加运行依赖。已有“MQTT 接收”流程节点仍是一条消息接收后退出，持续订阅通过工具栏“事件触发”单独配置。

## 使用

1. 准备需要执行的完整工程，打开“事件触发”。填写消息服务器、主题、内容格式、QoS、连接及订阅应答超时，按需配置 TLS/证书和密码环境变量名。
2. 设置接收消息写入的流程变量，默认 `mqttEvent`。在算子参数的变量绑定表单中可读取 `mqttEvent.value` 或其子字段，例如 `mqttEvent.value.count`。接收对象还包含实际主题、接收时间、QoS、保留/重复标记、字节数和平台消息 ID。
3. 设置等待队列容量、消息有效期、队列满时策略和重连间隔；可指定消息内容中的业务去重字段，例如 `requestId`。
4. 启动事件订阅。服务器捕获工程、输入图像/点云及本次脚本信任的快照，后续浏览器编辑不改变该会话。Python 仍需启动前明确启用可信脚本。
5. 用统计表查看接收、成功、失败、排队、丢弃、过期、重复、无效和重连数量。关闭浏览器不停止订阅，第二个客户端可读取状态、载入会话工程快照和停止。
6. 点击“停止订阅”、状态条的“停止事件触发”或工具栏“停止”。等待消息会丢弃，当前流程取消并按既有运行时语义处理变量；不自动执行下一个消息。

演示“流程控制 → MQTT 事件触发 · 消息到变量与运行画面”只载入工程，不立即执行。启动默认本机模拟订阅后，点击“发送模拟测试消息”；运行模式显示执行次数、工件数量 3、通过状态，以及最近消息的字段表。测试按钮仅支持当前本机模拟订阅，不向外部设备发送数据。

演示“MQTT 事件 → 相机采集 → 数量检测”进一步运行模拟相机和真实 OpenCV 轮廓算子，以检测数量对比消息的目标数量。运行画面同时显示本轮标记图和消息字段表；默认检测 3 个轮廓。消息触发流程不等于相机的物理触发同步。

## 执行与恢复语义

- 全服务目前只允许一个 MQTT 事件会话；会话占用运行平台，等待消息时也保持互斥。手动执行、连续检测、变量写入和保存工程须先停止会话。Node-RED 本身的流程仍是独立运行系统。
- 每条入队消息串行启动完整工程，不允许流程重叠。消息输入在该轮变量事务内部注入；固定类型校验、运行失败或取消时不发布本轮变量变更。成功后接收消息成为该流程变量的当前值，后续节点也可显式修改它。
- 运行历史标注启动方式为 MQTT 事件触发，并保留原始接收对象、执行结果、变量与错误。平台生成的消息 ID 只用于本平台追踪，不能代替发送端的业务编号。
- 断线后按配置间隔尝试重连，包括连接被拒绝；重新连接后重新发送订阅请求。TLS 使用现有严格证书及主机名校验。订阅授权被拒绝或订阅应答超时则停止会话，需检查配置后重新启动。
- 采用 clean session。断线期间消息不保证保留；平台已入队且尚未过期的消息可继续执行。收到的消息不等于设备动作已经完成，MQTT QoS 也不能证明工业动作恰好执行一次。
- 默认不接收服务器保留消息。显式允许时，重连重新订阅可能再次收到保留消息；按业务需要设置去重字段。
- 去重按“实际主题 + 内容中的标量字段”保存最近 1000 个已接收入队的键。字段须为数值、开关或不超过 200 字符的文本；缺失/无效字段记为无效消息。被丢弃的新消息不进入缓存；已经入队但后来过期或被丢弃的键仍可能保留。缓存仅属于当前会话，不是持久化的业务幂等账本。
- 流程失败、归档/监控写入失败、队列默认溢出或会话状态写盘失败均停止会话。不会自动重跑失败流程；已经发送到 PLC、串口或消息服务器的外部动作无法随变量回滚。
- 服务正常关闭先停止会话并清理连接；重启不自动重连或重放消息。异常退出留下的活动会话在启动时标记“已中断”。等待队列、去重缓存和工程输入快照不跨重启恢复；需检查设备状态后重新启动。

## 容量和配置

| 项目 | 范围或策略 |
|---|---|
| 等待队列 | 1–100 条，解码后的队列对象总计最多 4 MiB，不含正在执行的消息 |
| 单条消息 | 原始消息体最多 64 KiB，解码对象最多 512 KiB |
| 消息有效期 | 100–3600000 ms，从接收至开始执行检查；不限制已启动流程的运行时间 |
| 重连间隔 | 200–60000 ms，固定间隔 |
| 连接/订阅应答超时 | 100–60000 ms |
| 满队列策略 | 默认停止；也可显式丢弃最早等待消息或新消息，并计数 |
| MQTT 连接互斥 | 与单次 MQTT 节点共用客户端标识锁，总计最多 8 个任务 |

无效编码/格式的消息被拒绝并计数，后续合法消息仍可执行。解码长度校验不表示进程对恶意网络流量具有硬内存隔离。会话状态文件只持久化受支持的连接配置及统计摘要，密码/私钥密码只保留环境变量名称，证书内容不通过状态接口返回。

## 验收与范围

`npm run test:mqtt-trigger` 包含 11 项专项单元/真实 TCP 协议测试，以及独立服务器 HTTP 验收。覆盖串行队列、输入事务和历史、保留消息、业务去重、格式错误、满队列取消、丢弃/过期、固定类型回滚、写盘失败、异常恢复、真实消息服务器断线重连/重新订阅、连接中立即停止和客户端标识冲突。HTTP 验证管理员认证、互斥、工程快照、三条消息执行、变量/HMI、事件历史、跨客户端停止和服务关闭重启不重放。

相关运行时、流程、HMI、历史和 MQTT 回归共 132 项通过，`npm run check` 通过。HTTP 还运行真实模拟相机/OpenCV 链路，确认检测 3 个目标、判定通过及输出标记图。

Windows 浏览器已验证 TLS 字段显隐、模拟订阅、3 条消息执行、相机/真实算子链路、表格/运行画面、第二客户端读取和停止，以及保存配置刷新后再次启动；截图 `artifacts/sieans-mqtt-event-runtime.png`。仍需真实厂区消息中间件、长期压力与故障注入、Linux 验收。此功能不包含 OPC UA 长期订阅、相机长连接、TCP/串口监听、设备应用应答状态机、多个工程调度或持久化离线消息队列。
