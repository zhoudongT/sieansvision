# 原始 PNG16 深度文件导入

当前工作目录在“打开点云 / 深度图”窗口增加“导入原始 16 位 PNG 深度图”表单。使用已安装的 OpenCV/NumPy，无相机或厂商 SDK 也可复现投影及后续 3D 流程。冻结的 0.3.0-dev-candidate-2 ZIP 不包含本次新增功能。

## 文件和标定要求

- 文件必须为 16 位、单通道、无损 PNG，最多 12 MB / 400 万像素，单边最多 32768。拒绝 8 位、彩色、调色板及伪彩图，不自动拉伸数值或把普通图像估算成真实深度。
- 原始值表示已校正针孔相机的光轴 Z 深度。**不是沿像素射线的径向距离**，不支持尚需镜头去畸变、鱼眼或任意厂商专有编码。需确认数据来源，填写与此图像分辨率、裁剪、校正结果对应的 `fx/fy/cx/cy`；不凭图像尺寸猜测焦距。
- 表单填写“每个原始值对应毫米”。例如 1 表示原始值 975 为 975 mm，0.1 表示原始值 9750 为 975 mm。后台沿用平台的米/原始值契约，输出点云统一为毫米。
- 0 始终无效，可指定额外无效值，例如 65535。距离范围以毫米填写；保留范围内有效采样点。上下限包含端点；没有有效采样点时失败。
- 采样按二维像素网格，从像素 `(0,0)` 开始，每隔指定步长取一点。候选网格最多 20 万点，超限要求明确增大步长，不自动改变采样配置。原图有有效值但采样网格恰好未取到时，也明确失败。

采用零起始像素坐标和标准针孔反投影：`Z = raw × scaleMeters`，`X = (u-cx) × Z/fx`，`Y = (v-cy) × Z/fy`，然后由米换算为毫米。X 向右、Y 向下、Z 向前，不做机器人坐标变换。公式和独立对比依据：[Open3D 官方接口](https://www.open3d.org/docs/release/tutorial/geometry/python_interface.html)、[官方 GitHub 仓库](https://github.com/isl-org/Open3D)。代码直接使用 NumPy 实现投影，导入本身不依赖 Open3D；后续 3D 算子仍按原有依赖运行。

## 输入、流程和保存

导入成功后，同时替换输入深度与点云，并清除原输入图像，避免把无关的原图当作对齐彩色图。失败或导入期间输入发生变化时保留原输入。文件单位选项仅用于原有点云导入，不改变这里的毫米输出。

“深度图”标签显示固定距离范围的伪彩预览，黑色为无效或范围外；原始 PNG 文件字节和全部 16 位深度值独立保留。点云采样、距离过滤、后续点云裁剪不裁剪/改写原始深度栅格。预览不等于测量数据。

单次运行、执行所选、连续运行及 MQTT 事件任务都提交同一输入帧的深度和点云；服务端任务使用私有快照。Python 使用 `ctx["depth"]`，3D 算子处理 `ctx["cloud"]` 对应的数据。子流程工作区、临时演示返回保留原输入，切换点云文件/清除点云、重新导入图像或载入服务器任务工程快照时清除旧输入深度。

工程保存的是流程和参数，**导入文件及内参输入不作为工程的永久采集源保存**，刷新后需重新导入；没有自动按路径重新读取磁盘文件。启用“运行历史 → 保留采集和输出的图像、深度及点云”后，可归档运行输入的原始深度及点云。仍受 HTTP 35 MB、深度/点云各自大小及历史 50 MiB 限制，过大时需增大点云采样步长或缩小输入文件。

## 演示与验证

“演示案例 → 3D”增加三个合成案例，`scripts/generate-depth-file-samples.py` 可重新生成：

| 演示 | 已知结果 |
|---|---|
| 原始 PNG16 到顶面测量 | 64×48、fx/fy=100，背景 1000 mm、顶面 975 mm；裁剪后 200 点、采样顶面宽 185.25 mm |
| 采样步长影响 | 步长 2，顶面 50 点、采样宽 175.5 mm；不把采样包围尺寸称为实体实际尺寸 |
| 0.1 毫米原始单位 | 原始深度乘十、比例除十，仍获得 200 点及 185.25 mm |

三个演示均提供数值和交互点云 HMI，保留完整原始深度图。`npm run test:depth-import` 验证数值、Open3D 独立投影一致性、原始字节/无效值、超限/错误文件拒绝、表单单位换算/异步输入保护、真实流程/连续帧快照、HTTP/历史与重启后重新提交输入。当前没有彩色纹理映射、畸变校正、真实设备精度、现场节拍或 Linux/新界面真实窗口验收。
