# 通用串口报文通信

工作台“工业通信”新增**串口报文通信**；Node-RED 对应 `machine-serial_exchange`。复用锁定的 [pySerial 3.5](https://github.com/pyserial/pyserial)（BSD，许可证位于 `third_party/pyserial/LICENSE.txt`）。实现依据 [官方串口 API](https://pyserial.readthedocs.io/en/latest/pyserial_api.html)，用于 RS-232、USB 虚拟串口及带自动方向控制的 RS-485 适配器的自定义报文。不能据此承诺所有设备、驱动和 RS-485 方向控制方式兼容。

## 使用

1. 添加“串口报文通信”，选择外部设备。Windows 填写 `COM3` 等名称，Linux 填写 `/dev/ttyUSB0` 等路径。
2. 可在“工业通信 → 刷新串口列表”查看设备、描述和硬件标识，点击“用于所选模块”。此操作只设置路径，不打开端口；也适用于 Modbus RTU 节点。
3. 按设备手册选择波特率、5–8 数据位、N/E/O/M/S 校验、1/1.5/2 停止位。系统/驱动可能拒绝不支持的组合，错误会返回到节点。
4. 选择无流控、RTS/CTS、DSR/DTR 或 XON/XOFF。对应硬件流控开启时隐藏手动 RTS 或 DTR 初始状态。串口每次打开/关闭可能让设备复位或产生控制线脉冲，实际行为由驱动决定；设置初始状态不保证消除脉冲。
5. 选择发送并等待应答、仅发送或仅接收。仅接收不发送字节，也不清空已有输入；所需发送内容、接收完成条件按模式展示。
6. 参数和内容使用表单/字段表；发送和接收内容格式分别配置，可为 UTF-8 文本、结构化字段或 0–255 字节数组；例如发送文本测量命令，直接把结构化应答字段用于变量绑定。旧工程未设置接收格式时沿用原有消息格式。结构化数据在线路上以 UTF-8 JSON 编码，用户无需编辑序列化配置。少于 8 数据位时，发送内容连同头部/结束符必须能用所选位数表达。

## 报文和超时

发送支持原始字节、LF/CRLF/零字节结束符、2/4 字节无符号大小端长度头。接收支持对应结束符/长度头或固定字节数；长度不含头部本身。串口没有网络 EOF 完成条件。结束符不能出现在发送内容内，二进制数据宜用长度头或定长；首帧结束符和长度头不进入输出值。

每次执行只处理一帧，端口随后关闭。分段 UTF-8、分段结束符和长度头先按字节累积再解码。超长、无效结构化数据、无效 UTF-8、拔出或不完整报文超时均报错。结果 `trailingBytes` 仅统计首帧完成时已经读到当前缓冲区的尾随数据，未读取数据不计入且不会跨执行保留。

通信超时 100–10000 ms，从 Python 适配器开始计时，包含端口打开、写入、驱动发送队列排空及接收。Python 进程启动有额外开销，父进程在配置超时后另给 1500 ms 看门狗余量；挂起的驱动调用会被终止。取消会终止子进程，端口锁在进程退出后释放。禁止无超时 `flush()`，改为在期限内检查驱动发送队列。

默认保留已有输入。可明确勾选“发送前丢弃已有接收数据”，此时结果记录丢弃前读到的字节数；这个值不是设备消息数量。可能晚到的旧报文依然需要设备事务编号验证。没有自动重试、重连或业务确认。

`delivery=sent` 表示写入并完成相应发送处理，`received` 表示收到完整报文；`acknowledged=false` 不冒充设备动作确认。后续条件/脚本检查设备状态码。发送后失败或取消可能已经影响外部设备，平台变量回滚不能撤销这些动作。

## 资源与大小

- 真实端口内容最多 64 KiB，长度头/结束符另计；两字节长度头最大 65535 字节。
- 软件模拟固定使用 pySerial `loop://`、115200 / 8N1 / 无流控，含头部最多 4096 字节；模拟仅支持请求应答或仅发送。
- 普通串口和 Modbus RTU 共用服务器端口锁。Windows 的大小写及 `\\.\COMn` 别名归一到同一锁；POSIX 解析存在的符号链接。Windows 打开通常排他，POSIX 请求 pySerial 独占模式；不保证阻止忽略协作锁的外部程序。
- 工业 Python 适配器共享 8 个并发任务上限。路径参数只接受本地端口，不能通过设备路径传入 pySerial 网络 URL；软件回环由“模拟”选项显式选择。

## 验证与尚未完成范围

“演示案例 → 通信”提供扫码文本、结构化检测记录、定长二进制三个回环案例，结果写入 `serialReply` 流程变量。

`npm run test:serial` 包含：真实 pySerial 回环，分帧和缓冲处理，替身端口的分段读取/部分写入/断开/驱动队列超时/控制参数，Node 运行时三级变量及帧保留，端口互斥与取消，HTTP 工程保存/历史/认证/串口枚举，以及实际 Node-RED 的输入消息、表单常量和 Catch 错误。

Windows 上运行了 6 项 Python 测试；另有 POSIX PTY 测试在非 POSIX 环境明确跳过。替身和软件回环不构成真实串口硬件、RS-485 电气时序或 Linux 验收。长期监听扫码事件、跨节点复用端口、事务队列、软件 RTS 控制的 RS-485 方向切换仍未实现。


## Windows 虚拟端口补充验证

当前机器枚举到明确标为 `ELTIMA Virtual Serial Port (COM1->COM2)` / `(COM2->COM1)` 的配对端口。已使用 Windows 实际串口驱动打开这对虚拟端口：发送文本命令、读取分段中文；文本命令与结构化应答分别编码；读取四字节小端头的二进制数据；等待期间 Modbus RTU 被同端口锁拒绝；取消后释放并重新打开；无应答超时报错。未打开蓝牙端口或访问物理设备。

这项验收脚本是显式启用的 `tests/test_serial_virtual.cjs`，通过 `SIEANS_TEST_SERIAL_CLIENT` 和 `SIEANS_TEST_SERIAL_PEER` 指定端口；配套 Python 脚本会先核对枚举描述，拒绝普通/物理串口及不匹配的虚拟配对。该脚本不加入默认回归，以免其他机器误访问设备。日志为 `artifacts/serial-windows-virtual-final.log`。此验证证明 Windows 虚拟驱动路径，不证明现场设备电气兼容性。
