# 成功与失败连线

选择任意算子，在“连线与数据来源”表中设置其输出连线条件：成功后执行（默认）、成功时执行、失败时执行。条件判断节点还提供判断成立/不成立。流程图连线显示成功或失败标签；参数与错误结果均为表单和表格，不需要编辑配置文本。

默认和成功连线只在上游成功时激活。失败连线只在上游实际执行且失败时激活：跳过的节点不会产生错误事件。失败节点保留错误信息，普通下游跳过；错误分支可绑定该节点结果中的 error、operation、failed。失败分支沿用失败算子输入的图像、点云和深度，不传播部分输出。

处理节点正常结束后，可通过“分支汇合”与正常分支重合。普通多输入节点要求所有输入激活；分支汇合要求恰好一路激活。错误处理自身报错时，只有它也有可执行的失败连线才继续转交；否则整轮失败。没有失败连线的节点报错仍立即终止。执行所选只包含上游依赖：下游处理节点不在执行计划中时，不会吞掉所选节点错误。

每个有错误分支的节点在执行前保存本轮变量快照；失败后撤销该节点对全局、流程、模块变量的修改，保留先前成功节点尚未提交的变更供后续处理。所有路径正常结束才提交整轮变量；后续未处理错误或取消会回滚整轮。取消任务不触发错误分支。工程、脚本信任、插件预检和最终提交等流程级错误不通过算子分支恢复。

设备写入、网络报文、脚本文件写入等外部副作用不能由变量回滚撤销。错误分支不自动重试设备操作。此机制没有改变 Node-RED 自身的 Catch 节点；工作台工程使用这里的分支，Node-RED 流程仍使用原生错误机制。

错误被处理后，作业状态为完成，界面保留失败节点及“已转入错误分支”说明、错误数量和错误记录。连续检测将该轮记为完成；这表示流程执行完毕，不等同产品合格。需要在错误处理分支显式设置 NG/报警变量，并在运行画面绑定这些质量判定。历史保存原始错误、处理标记和最终变量。

演示分类“流程控制”新增：算子失败→错误分支→汇合、算子成功→跳过错误分支、错误处理失败→停止并回滚变量。`npm run test:flow-control` 包括既有条件/延时测试和 7 项错误路径测试，以及真实 Python 算子失败后沿用原图检测、工程保存和三个演示的 HTTP 验收。运行时/历史和图结构/连续检测回归也已验证。
