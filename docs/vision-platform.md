# 视觉开发与运行平台

当前已实现文件图像、2D/YOLO 算子、自由连线、服务器作业、Python 自定义脚本、三级变量，以及首批 3D 点云输入/交互查看/滤波/平面/聚类/测量/高度体积估计/配准。3D 安装、数据格式、限制和验证见 [cloud-operators.md](cloud-operators.md)。完整目标及未完成项目见 [platform-roadmap.md](platform-roadmap.md)：更多 3D 检测、工业/体积相机、通信与完整运行平台继续实施。

## 工作台

打开 `http://127.0.0.1:1880/vision/`。

1. 点击“打开图像”，或“载入演示”。几何、条码和 OCR 会载入相应演示图。
2. 点击左侧算子接到选中节点之后，或拖入画布后自行连线。节点自由摆放；执行关系由连线决定。
3. 选中算子，通过功能表单修改参数，数组和结构体使用字段表；在输入图拖动可框选 ROI。定位算子可切换到“定位模板”框选模板。
4. “执行所选”执行目标及上游依赖；“运行流程”按连线拓扑执行。预处理更新下游图像，检测/识别保留输入图。运行作业在服务器执行。
5. 切换结果标签查看各步标记图片、坐标、识别内容及耗时。停止按钮在当前算子结束后停止后续步骤，单个后台任务超时为 120 秒。
6. 保存工程后，服务器 `data/vision-project.json` 保留算子和参考图。重新打开页面会加载工程。每次检测的输入图不写入工程，需要重新选择。
7. “导出工程 / 导入”用于 JSON 备份；已移除 Node-RED 流程导出入口。工程 JSON 保存图、参数、脚本和变量初始值；运行变量独立保存在服务器。

管理员运行模式：`http://127.0.0.1:1880/vision/?mode=run`，隐藏编辑控件，仍使用管理员身份。独立操作员入口为 `/vision/operator.html`，运行管理员已发布的方案，并由服务器实施权限隔离；支持多操作员账号、操作记录和发布时指定的连续检测策略，见 [发布与操作员运行](operator-access.md)。

Node-RED 入口：`http://127.0.0.1:1880/editor/`。算子在“视觉算子”分类中。

## 本机与跨平台安装

已在当前 Windows 环境安装 Python 虚拟环境和推理依赖。启动：

```sh

```


```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r vision/requirements.txt

.venv/bin/python -m pip install -r vision/requirements-3d.txt
```

当前 `models/` 已下载官方 `yolov8n.pt`、`yolo11n.pt` 用于演示；新部署请复制可信模型，或从官方资产下载。运行时不会自行下载权重。YOLO 默认 CPU，首轮耗时包含模型加载。当前仅支持目标检测，不包含训练、分割、姿态和分类任务。

## 算子范围

| 算子 | 已实现 | 参数示例 |
|---|---|---|
| 图像预处理 | 灰度、模糊、二值化、Canny、开闭运算、腐蚀膨胀 | `{"method":"threshold","threshold":127}` |
| 模板定位 | 平移、角度离散搜索、多尺度、分数、中心与偏移 | `{"angleStart":-30,"angleEnd":30,"angleStep":5,"scales":[0.9,1,1.1],"minScore":0.85}` |
| 几何查找 | 直线、圆、边缘、外轮廓 | `{"feature":"circles","minRadius":10,"maxRadius":80,"votes":30}` |
| 测量标定 | 两点等比例标定、两点测距、外接矩形尺寸、圆直径、原点偏移 | `{"points":[[50,70],[250,70]],"calibration":{"points":[[0,0],[100,0]],"distance":10},"unit":"mm"}` |
| 条码 | ZXing-C++ 多条码、QR、Data Matrix 等 | `{}` |
| OCR | 本地中英文识别、文本框、置信度 | `{"minConfidence":0.5}` |
| 缺陷对比 | 与良品图的灰度差分、区域筛选、面积比例判定 | `{"differenceThreshold":30,"minArea":20,"maxDefectRatio":0.001}` |
| YOLO | YOLOv8 / YOLO11 检测模型、类别筛选、NMS、画框 | `{"model":"yolo11n.pt","confidence":0.25,"iou":0.45,"imageSize":640}` |

公共 ROI：`{"roi":[x,y,width,height]}`，以原图左上角为坐标原点，x 向右、y 向下。所有结果坐标均已还原到原图，单位默认像素。

定位模板需要有纹理，对称图案不能可靠判断正反；旋转角度精度取决于搜索步长。测量尚未补偿透视和镜头畸变。缺陷检测要求参考图尺寸、位置和光照一致，结果为疑似差异区域，不能自动解释差异类型。这些功能需用实际产品样本验证阈值和精度。

## 插件消息接口

```js
msg.image = 'data:image/png;base64,...'; // 或纯 base64
msg.reference = 'data:image/png;base64,...'; // 模板/良品图，可选
msg.visionParams = { roi: [0, 0, 300, 200] }; // 可选，覆盖节点参数
```

每个视觉节点有两个输出：

- 输出 1：`msg.payload` 为结构化结果，`msg.vision` 包含 result、annotatedImage、elapsedMs、imageSize；`msg.image` 用于继续串联。
- 输出 2：`msg.payload` 为标记图像 data URL，便于接显示组件。

预处理更新 `msg.image`，使用 PNG 保留像素；其他节点保留原图，防止绘制的标记进入下一步检测。模板可以存入节点 `reference` 配置，消息中的 reference 优先。失败通过 Node-RED Catch 节点捕获。

图像输入限定编码数据，不接受客户端传入任意服务器文件路径。已加入 USB UVC / GenTL 单帧采集适配器与 `machine-camera_capture` 节点，输出同样的 `msg.image` 复用后续流程，详情见 [相机采集](camera-acquisition.md)。高帧率阶段仍需升级为共享图像引用与长连接采集服务。

内置节点包：`plugins/node-red-contrib-machine`。Python 引擎：`vision/engine.py`；进程与队列：`lib/vision-client.cjs`。新的算法可作为 Node-RED 插件独立发布；当前内置 Python 操作通过 operation 分发。

### 自由连线流程图（2026-10-15）

工作台升级为节点与有向连线构成的图。节点坐标与执行顺序分离，支持分支、汇合、跨层及侧向连线。点击工具箱算子会接到选中节点之后；拖入画布则创建待连接节点。节点上/左为空心输入端口，下/右为实心输出端口；可以拖拽端口，也可依次点击输出、输入端口建立连接。选择连线后按 Delete 或点击“断开”移除；Esc 取消连接。节点可拖动，也可聚焦后按方向键移动（Shift 为大步长）。画布支持空白拖动平移、缩放、适应、自动排列、展开编辑，以及折线/曲线显示。

执行采用拓扑依赖顺序，同层节点当前由本地引擎逐个调度，不承诺并行推理。汇合节点等待所有上游成功完成；在模块参数中选择一个上游作为图像输入（实线），其余连线是执行依赖（虚线）。预处理节点传递处理后图像；识别节点传递未画标记的输入图像，识别结果显示于结果表。当前不包含多图融合、条件分支、结果字段绑定或循环体；循环、自连接、重复和悬空端点会被拒绝。完整运行前检查孤立节点；执行所选仅运行该节点及所需上游，不受其他未连接草稿节点影响。错误终止后续执行；停止在当前算法结束后生效。

工程使用 version 2，增加 edges、节点 position、imageFrom 和 sourcePosition，保存和 JSON 导出保留连接及布局。version 1 工程自动迁移成等价串行图；读取迁移不会自动覆盖服务器文件。新工程不能由旧版编辑器读取。

新增第 14 个演示“分支与汇合 · 无序连线”：源图像分成二值化、圆检测两路，两路汇合到编号 01 的轮廓节点；实际执行编号 02、03、01，结果为 3 个轮廓。

### 服务器运行时、Python 和三级变量（2026-10-15）

完整流程改由 `lib/runtime.cjs` 在服务器执行。浏览器创建作业、按游标获取增量结果，并发送取消请求。当前一个服务器同时执行一个流程作业，拒绝重入；保留最近三个作业，每次结果最多 40 MB。普通视觉算子取消在当前调用结束后生效；Python 进程收到取消立即终止。服务器重启会丢失内存作业记录，重连自动接管和连续任务仍需后续实现。

新增 `script` 与 `variables` 两类流程节点，以及顶部“变量管理”。`project.id` 是工程持久 ID，节点仍使用原有 ID。全局变量在服务器各工程间共享，流程变量按工程 ID、模块变量按工程+节点 ID 隔离。工程 `variables`、节点 `variables` 是可选初始值；运行值保存在 `data/runtime-variables.json`，按初始值补全缺失键。导入同一工程 ID 会使用同一流程状态。变量管理读写当前值，不修改工程初始值。全局/流程/模块值支持 JSON 数字、布尔、字符串、数组、对象、null，拒绝非有限数、原型保留键和过深/过大数据。

每次作业从变量快照执行，全部成功后原子写入文件；任何异常或取消均不提交本次变量修改。编辑带 revision 检查，运行中拒绝写变量，避免覆盖并发修改。此事务只涵盖平台变量，不涵盖脚本文件/网络/设备副作用。

普通算子的参数可使用精确引用（保留值类型，不进行字符串 eval）：

```json
{"threshold":{"$ref":"flow.threshold"},"minArea":{"$ref":"global.minArea"}}
```

`module.name` 读取当前模块变量；`results.NODE_ID.count` 读取有依赖路径的上游结果。未连线的兄弟节点结果不能被引用。变量赋值节点通过 `scope/name/mode/value` 配置；`mode` 为 `set` 或数值 `increment`。

Python 节点定义 `run(ctx)`，输入 `ctx["vars"]`（global/flow/module）、`ctx["results"]`（上游 ID→结果）、`ctx["image"]`（base64/data URL）、`ctx["params"]`（节点 arguments）。返回字典：`result` 为结果对象；`variables` 为要替换的作用域对象，未提供的作用域保持原值；可选 `image` 作为下游图像。print 日志出现在运行日志。示例：

```python
def run(ctx):
    values = ctx["vars"]
    values["global"]["cycles"] = values["global"].get("cycles", 0) + 1
    values["module"]["calls"] = values["module"].get("calls", 0) + 1
    return {"result": {"passed": True}, "variables": values}
```

脚本在独立 Python 子进程运行，默认 5 秒、可配置 100–30000 ms，代码最多 100 KB、输出最多 2 MB、日志保留最后 8000 字符。Windows 下强制 UTF-8，避免中文输入损坏。只运行受信任脚本：进程超时和 `-I` 不是安全沙箱，代码拥有服务器账户权限，可能启动额外进程；不要依赖它隔离不可信代码。导入/切换工程后需重新勾选“运行可信脚本”；没有该显式标志，服务器拒绝执行含脚本的计划。

API：`POST /api/vision/runtime/jobs`（project/image/target?/allowScripts?）、`GET /runtime/jobs/:id?after=N`、`POST /runtime/jobs/:id/cancel`；变量 `POST /runtime/variables/read` 和 `PUT /runtime/variables`（project/values/revision）。这些均位于 `/api/vision` 下，并沿用工作台管理员验证。

新增第 15 个演示“识别结果 → Python → 三级变量”。浏览器实测 count=3、passed=true，并在变量表显示全局 demoCycles、流程 lastCount、模块 calls；编辑 threshold=127 后回读一致。验证：18 项流程/运行时测试、11 项算法测试、HTTP/工程存储/Node-RED 集成全通过。包含真实 Python 执行、中文日志、超时与取消、状态隔离、失败回滚、持久化及修订冲突。


### 功能表单与变量表格（2026-10-15）

SIEANS 工作台不再提供原始 JSON 参数、变量编辑器或结果标签页。旧工程文件和后台接口仍保留原有结构，导入、保存、导出继续兼容。以下界面说明替代前文有关高级 JSON 编辑的描述。

- 模块配置：常用参数按功能展示表单；通过“添加设置”配置检测区域、坐标、标定、矩阵和类别筛选等。已有扩展参数使用带类型的递归表格编辑。点云参考数据仍通过文件上传管理。
- 参数绑定：选择“绑定变量或结果”，填写变量范围，或选择已连接的上游模块及结果字段。后台自动生成引用。数组、结构体逐项编辑，数值、文本、开关、空值保留真实类型。
- 变量管理：按全局、流程和工程内全部模块展示变量；支持新增、改名、修改类型、删除及嵌套值编辑。运行当前值写入运行存储；工程初始定义应用到工程，之后需保存工程。全局值跨工程共享，初始定义仅针对流程和模块。保存的运行值优先于初始定义；删除当前值而保留初始定义时，下次读取恢复初始值。重新读取会丢弃未应用的表格修改。
- Python 节点：独立代码区编辑 `run(ctx)`，支持 Tab 缩进和“展开编辑”。输入参数表对应 `ctx["params"]`，可绑定上游结果和三级变量；输出绑定表将脚本 `result` 中的字段写入全局、流程或当前模块变量。字段可使用点分隔路径。输出绑定在脚本自带变量更新之后执行；字段缺失、重复写入同一变量、非法范围或名称使整个作业失败，变量事务回滚。
- 结果：仅保留模块结果表与运行日志，嵌套数组、结构体展开为子表格，大集合分批显示。脚本代码本身仍使用 Python 语法；日志中的完整 JSON 对象或数组（整段或独立行）转换为可展开表格，普通文本原样显示，后台保留原始日志。

验证：`npm run check`；`npm test` 的 20 项流程/运行平台测试、11 项 2D 算法测试及 HTTP/Node-RED 集成通过。新增测试覆盖脚本表单输入绑定、三级输出变量类型、缺失字段和重复绑定回滚。浏览器实测输入数值从 3 改为 4 后判定不通过，绑定上游 count 后判定通过；输出变量改名后写入 inspectedCount=3；数组变量 limits 的初始定义、改名、写入、重新读取仍为数值 12.5。

### 表单入口补齐（2026-10-16）

变量和脚本参数的绑定控件支持“来源 → 上游模块（结果来源时）→ 已定义字段”选择，同时保留字段路径输入。列表显示数据类型，支持数组元素及结构体子字段；“刷新变量列表”只读取当前工程的运行变量。全局变量、流程变量及当前模块变量按作用域隔离，工程初始定义也进入选择列表。上游字段来自最近运行结果，每个模块最多列出 500 项；修改参数清空结果显示时保留字段名称，执行时仍解析当轮实际值，不复用历史值。切换工程会清除字段缓存。未运行或未列出的字段可手动填写路径。

绑定处理方法时，方法值到执行阶段才确定，因此保留可能需要的参数表单；固定方法仍按灰度、二值化、圆、直线、点云裁剪等功能筛选字段。

- 变量及脚本输入表分列显示名称、数据类型、值或绑定、操作；嵌套数组和结构体沿用此形式。这里的类型描述当前值，尚不构成运行期固定类型约束。
- 预处理、几何检测、测量按所选方法展示相关参数。切换方法隐藏不适用设置，但保留原值，切回后继续使用。绑定方法选择器时保留可能需要的参数，具体方法在运行时解析。
- Node-RED 自定义视觉节点的参数文本框改为功能表单，扩展参数使用“添加参数”，坐标、标定及变换矩阵展开为表格；旧 `params` 序列化存储兼容。此约定适用于自有视觉节点，Node-RED 自带 Function/Debug 等通用开发工具仍保留其自身界面。
- 验证：语法检查、10 项运行平台测试通过。浏览器验证脚本输入 4 得到 count=3、passed=false；完整结构化日志显示为展开表；数组值 12.5 写入并回读；几何功能切为圆时隐藏轮廓面积；Node-RED 阈值改为 163，完成编辑后再次打开回读一致（未部署测试修改）。


### 变量总览与结构化文本界面（2026-10-16）

变量管理默认进入总览，用同一张表展示全局、流程与全部模块变量的作用域、名称、固定类型、工程初始值、运行当前值和校验状态。支持名称/模块搜索、作用域筛选及每批 50 行展开，编辑按钮跳转对应作用域。总览使用已应用的工程定义与最近读取/写入的运行快照；未提交草稿保留在编辑页，刷新仍会撤销草稿。全局变量没有工程初始值，明确标注为全局持久值。

有效对象/数组形式的结构化文本在变量和脚本输入中使用字段表编辑，提交时由后台格式序列化，保留文本类型。脚本输出仍通过字段绑定表配置；代码区保留语言源代码。结果表、运行画面的数值与表格组件自动将结构化数据转为表格；变量输入组件遇到结构化值时显示表格，并指引到变量管理编辑，避免将对象或序列化文本直接填进普通输入框。

验证：语法检查及 17 项流程图/HMI 回归通过；浏览器验证变量初始值 0 与当前值 3 对照、筛选及编辑跳转；在脚本输入字段表将 count 从 3 改为 4，脚本成功解析文本输入并写入整数 4 和文本输出，运行画面三种组件按表格呈现。


### 统一界面数据约定

新增算子、插件和脚本沿用以下界面要求：参数按功能显示表单；变量定义、作用域、类型、初始值、当前值及绑定显示表格；数组、记录和矩阵展开为子表。后台可继续使用 JSON，用户无需编辑序列化配置。Python 源码保留代码编辑器，输入、输出绑定与结构化日志使用表格。

结构化文本支持带说明前后缀及多段记录。编辑某一记录时保留文本类型、外围文字及未编辑记录原文；插件文本参数与内置文本参数复用同一字段编辑器。结果、变量及运行画面复用表格展示。普通文字或格式不完整的诊断信息按文本保留，不猜测缺失字段。变量总览扩大当前值列，避免嵌套表格挤压。
