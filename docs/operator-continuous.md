# 操作员连续检测

管理员在“发布运行方案”表单中勾选“允许操作员启动连续检测”，填写固定轮次间隔和执行次数，再发布服务器已保存的工程。间隔为 100–3600000 毫秒，从上一轮结束后计算；次数为 0–1000000，0 表示直到停止。设置和工程、脚本信任标记一起计入发布版本摘要。旧版发布方案仍能单次运行，但默认不开放连续检测，需管理员重新发布。更换连续设置也会产生新的发布版本，旧页面不能继续按旧版本启动。

操作员运行页出现“启动连续检测”按钮和只读统计表，展示管理员设定、运行状态、启动用户、完成/启动轮次、失败/取消轮次、最近耗时和下一轮时间。操作员请求只携带当前发布版本和输入图像/点云；不接受自带工程、目标模块、间隔、次数、脚本许可或来源标记。操作员不能在运行页修改连续设置；管理员工作台未保存或未发布的修改不影响正在运行的快照。

文件输入在启动时复制，每轮重复使用同一份数据；相机采集节点按已发布参数每轮重新采集。执行成功轮次不等于工件合格数量。关闭页面不会停止服务器连续执行，多客户端能看到同一发布会话的状态，任一获准的操作员可通过“停止运行”请求停止服务器当前任务。它沿用已有运行平台的全局停止行为，并非硬件急停。

每轮串行执行，完成与轮次等待期间都保留运行资源，避免其他流程、变量写入或重新发布插入。停止发生在等待期间时不再启动下一轮；停止发生在执行期间时取消当前作业，当前轮变量回滚，已成功轮次变量保留。设备写入不随取消回滚。执行、历史归档或监控持久化失败会停止后续轮次；服务重启不会自动继续，需要检查设备后重新启动。

会话统计与启动用户随连续检测状态保存，重启可查看最近会话的计数。意外中断的活动状态会标为“服务重启中断”。运行页只提供匹配当前发布版本的会话统计，不暴露其他开发会话的工程、配置、来源用户名或原始会话错误。每轮完整结果依旧归档到管理员运行历史。操作记录记录谁提交了连续启动及会话编号，HTTP 202 表示“已受理”，不能当作整批完成。

验证命令：`npm run test:operator-continuous`。包含旧发布兼容、固定设置校验/篡改拒绝、参数夹带拒绝、有限轮次、无限轮次停止、失败停止、当前轮取消回滚、资源保留、统计重启恢复、异常中断恢复、发布表单和运行页离线 DOM，以及多操作员实际 HTTP 运行。浏览器真实窗口、相机/PLC 实机连续生产和长时间现场运行尚未验收。本功能只在当前源码和预览，之前冻结的发布 ZIP 保持不变。
