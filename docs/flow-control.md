# 条件分支、汇合与延时

工作台增加三个流程块：条件判断、分支汇合、延时等待。配置使用表单与连线表；工程继续以 version 2 保存，旧工程未设置条件的连线维持原来的依赖执行方式。

## 条件判断

“输入值”和“比较值”可填写数值、文本、开关、空值，或绑定全局/流程/当前模块变量与上游结果字段。支持等于、不等于、大于、大于等于、小于、小于等于、文本包含、开关为是、开关为否。

等于/不等于采用严格类型，数值 1 与文本 "1" 不相等；大小比较要求有限数值；文本包含区分大小写；开关判断要求布尔值。数组、结构体不作隐式字符串或数值转换。引用缺失或类型错误会使作业失败，不能当作“不成立”继续执行。开关判断不解析未使用的比较值绑定。

在条件节点或它的直接下游模块参数中，“连线与数据来源”列出每条条件连线，可选择：

| 执行条件 | 行为 |
|---|---|
| 始终 | 上游实际执行完成后激活 |
| 判断成立 | 上游判断结果为 true 时激活 |
| 判断不成立 | 上游判断结果为 false 时激活 |

连线只允许在条件节点输出处设置判断条件。画布的上下/左右端口控制几何走线位置，不自动代表成立/不成立；实际规则以连线表和线旁标签为准。可以把同一结果连接到多个模块。新连接默认“始终”，应按实际流程设置。

## 跳过与两类汇合

运行时先按连线依赖拓扑排序，等待上游完成或跳过后，决定当前节点是否激活。节点数组顺序和画布位置不决定路线，仍不允许回路。

普通节点要求所有输入连线均激活；任何输入未激活，则该节点跳过，并沿下游传播跳过状态。跳过时不解析参数、不运行脚本、不访问相机或通信设备、不写变量。结果区、日志与节点状态显示“已跳过”，不把它显示成执行成功。其结果不进入脚本/变量绑定的可用结果集合，引用跳过分支的结果会明确失败。

互斥分支重新合并时使用“分支汇合”：

- 没有激活输入：汇合及下游跳过。
- 恰好一路激活：自动采用该路的图像、原始深度、点云；参数界面的数据来源为只读自动选择。
- 多路同时激活：报错并回滚本作业的变量变更，不按先后顺序任意挑选。需要等待多个并行上游并选定图像来源时，继续使用普通节点汇合。

汇合输出的 `value` 包含实际分支模块的结果，可在下游通过字段路径绑定，例如变量赋值节点的结果用 `value.value`。界面显示实际输入模块名称；后台结果记录 `inputFrom` 节点 ID。深度预览也沿本次实际分支追溯。

节点失败或停止仍回滚变量事务，已发出的设备操作不会回滚。若工程计划中含 Python 节点，启动仍要求启用可信脚本，即使某次可能跳过该脚本。

## 延时等待

通过表单填写 0–30000 的整数毫秒，可绑定数值变量；等待期间保留完整数据帧。停止会取消计时器并释放本次作业，变量不提交。等待不是实时系统时钟，不提供精确曝光或 PLC 同步保证。

## 演示与验证

“演示案例 → 流程 → 数量判定 → 合格 / 复检 → 汇合”：真实轮廓检测返回 3；条件比较值为 3 时执行合格赋值并跳过延时/复检，得到 `inspectionRoute=OK`。在表单把比较值改为 4 后执行延时和复检，合格分支跳过，得到 `inspectionRoute=RECHECK`。

13 项控制测试覆盖严格类型、相反分支、多路冲突、全分支跳过、执行所选、跳过结果引用、取消/回滚及数据帧选择；HTTP 测试覆盖工程条件连线保存与双向路线切换。额外 RGB-D 测试验证分支汇合实际采用深度或 2D 数据，避免残留另一分支的深度/点云。浏览器已验证比较值 3/4、执行/跳过计数、结果表和自动汇合来源。

## 与 Node-RED 的关系

参考开源 [Node-RED Switch 节点](https://github.com/node-red/node-red/blob/main/packages/node_modules/@node-red/nodes/core/function/10-switch.js) 的条件分流用途；本次实现针对 SIEANS 作业、变量事务和多通道数据帧，自行定义严格类型及汇合语义，没有复制上游源码。Node-RED 编辑器已有 Switch、Delay 等核心节点；本页新增块在 SIEANS 工作台执行，不声称将作业式互斥汇合直接等同于 Node-RED 的消息 Join。

浏览器补充验证：在等待时间表单输入 30000 ms，关闭后重新打开仍保留该值；运行进入等待后点击停止，流程取消且变量变更未提交。改回 250 ms 后可重新运行。基础数值/文本字段现在在有效输入时即时提交，避免依赖失焦事件导致使用旧参数。

循环、子流程、持续采集、外部事件触发与后台作业队列仍在实施清单中。
