# 子流程与循环

“子流程管理”在工程中创建、命名、编辑和删除可复用定义。进入编辑后使用原有拖拽画布、端口连线、参数和变量表单；顶栏选择输出节点，再返回主流程。最多 20 个定义，每个最多 50 个节点。已有调用的定义禁止直接删除，需先修改调用节点。工程保存包含所有定义；在子流程编辑期间点击保存仍保存完整主工程，不会用编辑中的局部画布覆盖主工程。

工具箱“流程控制”新增“子流程调用”和“循环子流程”。从列表选择定义，用输入变量表传参。输出节点只决定返回哪一路结果和图像/点云/深度，子流程中所有已连接且激活的节点仍按依赖执行。未连接的草稿节点阻止运行；输出节点未激活或失败时报错。内部识别叠加图用于展示，实际输出数据帧仍遵守算子原有规则，避免把绘制框传给后续算法。

每个调用点有独立的局部流程变量和内部模块变量。输入变量写入子流程局部作用域，可绑定父流程变量或上游结果；不直接覆盖父流程的流程变量。默认每次调用重置，选择保留状态后按该调用点沿用上次成功运行的局部状态；显式输入始终覆盖同名历史值。一次循环内各轮共享这次调用的局部状态。系统提供只读轮次变量 flow._iteration 和 flow._iterations（从 1 开始），输入表不能占用这两个名称。

全局变量在子流程内可读取和更新，但随主流程整体提交；子流程失败时不发布中途局部/全局变更。子流程错误可接主流程的失败连线，内部也可使用成功/失败连线与互斥汇合。主流程后续失败或取消时，整个作业的变量均不提交。设备写入、网络报文和脚本文件副作用无法回滚，不自动重试。

循环有两种方式：固定次数执行，或每轮执行后检查输出结果中的布尔字段，达到指定开关值就停止。次数/最大轮数为 1–100 的整数，也可绑定变量或上游结果。停止字段必须存在且为布尔值，不能把数值或文本强转为开关。达到最大轮数仍未满足条件会报错，可由外层失败连线接管；不作为正常成功返回中途状态。可选择每轮沿用上一轮的数据帧，或重新使用本次调用的原始输入。

同一作业最多 4 层调用，禁止直接或间接递归；主流程和所有调用/循环合计最多 1000 次节点访问，跳过节点也计入。访问和结果内存预算超限作为作业级错误终止，不由算子错误分支吞掉。结果累计仍限制为 40 MB，调用点持久状态限制为 1 MB，并遵守既有变量深度、总存储和固定类型约束。执行所选仅包含所选主节点与上游，但对子流程执行完整内部计划。

取消使用同一个作业控制器传到内部延时、脚本及支持取消的设备适配器。已经发出的普通视觉推理仍需等待引擎返回后停止，不宣称能强行中断 CUDA/OpenCV 运算。循环轮间和较长纯计算节点序列会让出事件循环，避免取消请求被同步循环饿死。内部 Python 仍需本次可信脚本授权；所有将调用的脚本和插件在主流程执行前预检，不能通过子流程绕过权限或固定插件版本。

结果以表格展示完成轮次、是否提前停止、输出节点结果、局部变量、每轮结果及内部执行明细。明细包含轮次、节点编号、算子类型、跳过/错误处理状态、错误和耗时；不在每行重复保存图像。失败明细也随错误分支或运行历史保留。调用点的局部持久状态归属于该主节点的模块作用域。

演示分类“流程控制”提供：复用子流程零件检测、计数达到 3 提前停止、循环达到上限转入报警分支、3D 点云测量 3 轮。使用 `npm run test:subflows` 验证 13 项执行测试和真实 HTTP/OpenCV/Open3D/Python 链路；既有流程/错误分支/历史/连续检测回归另行覆盖。

这实现工作台内可复用定义与有界循环。Node-RED 继续使用其原生 Subflow/消息路由，不把工作台定义自动转译为 Node-RED 子流。暂不包含递归/无限循环、自动重试、单独的 break/continue 节点、跨工程子流程库、独立版本发布和子流程内独立 HMI。
